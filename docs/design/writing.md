# 화면 글쓰기 가이드 — 신한1학사 앱의 말투

> 2026-11-20 자료조사 세션 초안(W1). 화면에 나오는 모든 글(버튼, 카드 설명, 안내, 오류, 빈 상태, 확인 시트, 알림)의 기준이다.
> `docs/design/rules.md` 5절 "문구"는 이 문서로 옮기고 거기에는 연결 한 줄만 남기자고 제안한다(DESIGN·총괄 결정).
> 시트에 저장하는 값(`docs/contracts/vocabulary.md`)은 바꾸지 않는다. 이 문서는 **화면에 보이는 말**만 다룬다.
> 실제로 고칠 문구 목록은 `docs/design/writing-audit.md`.

---

## 0. 한 문단 요약

이 앱의 글은 **바쁜 동료에게 건네는 쪽지**처럼 쓴다. 한 문장에 한 가지만, 주어보다 할 일을 먼저, 꾸밈 없이. 교사에게는 짧고 담백하게, 학생에게는 친절하게 이유를 붙여, 학부모에게는 정중하게 걱정을 덜어 주는 쪽으로. 무엇이 잘못됐는지 말할 때는 사과도 탓도 하지 않고 **고치는 방법**을 쓴다.

## 1. 누가 읽는가 — 세 독자

| | 교사 | 학생 | 학부모 |
| --- | --- | --- | --- |
| 언제 읽나 | 저녁 자습 감독 중, 교무실에서 틈틈이. 한 손에 휴대폰 | 쉬는 시간, 기숙사에서. 자기 일만 궁금하다 | 퇴근 뒤 집에서 가끔. 앱 용어를 모른다 |
| 바라는 것 | 오늘 할 일과 결과를 빨리 | 내가 무엇을 해야 하는지, 왜 그런지 | 자녀가 괜찮은지, 학교가 연락할 일인지 |
| 어조 | 담백한 업무 말투. 동료끼리의 존댓말 | 친절한 안내. 규칙을 설명하되 훈계하지 않는다 | 정중하고 차분하게. 불안을 키우는 말을 피한다 |
| 끝맺음 | 합니다체. 지시는 "~하세요"가 아니라 동작 이름(버튼)으로 | 합니다체 + 부탁은 "~해 주세요" | 합니다체 + 부탁은 "~해 주세요" |
| 문장 길이 | 한 문장 25자 안팎 | 한 문장 30자 안팎, 카드 설명은 두 문장까지 | 한 문장 35자 안팎, 이유를 한 번 더 |
| 앱 용어 | 그대로(OUT, 특이사항, 확정·요청, 학·가) | 처음 나올 때 한 번 풀어 준다(OUT이란) | 되도록 풀어 쓴다(아래 7절 "학부모 화면 표기") |

### 존댓말 수준

- 모든 독자에게 **합니다체**를 쓴다. 해요체("저장했어요")와 반말은 쓰지 않는다.
- 부탁은 "**~해 주세요**". "~하세요"는 명령처럼 들리므로 학생·학부모에게 쓰지 않는다. 교사 화면에서도 안내문에는 "~해 주세요"를 쓴다.
  - 학생: "다음 달 시간표를 내 주세요." (O) / "시간표를 제출하세요." (X)
- "~하시기 바랍니다", "~하여 주시기 바랍니다", "~하십시오"는 공문 말투라 쓰지 않는다.
- 높임은 한 문장에 한 번이면 충분하다. "선생님께서 확인하시면 확정되십니다" → "선생님이 확인하면 확정됩니다."

## 2. 문장 쓰는 법

1. **한 문장에 한 정보.** 쉼표로 이어 붙이지 말고 마침표로 끊는다.
2. **할 일을 앞에.** "시간표 제출 기간은 3월 25일(목)까지이니 기간 안에 내 주세요" → "3월 25일(목)까지 시간표를 내 주세요."
3. **명사를 늘어놓지 않는다.** "사전 특이사항 입력 및 격자 정리 화면" → "특이사항을 미리 넣고 출석부를 정리하는 화면".
4. **쉬운 말로.** 미설정 → 아직 안 정함, 해당 없음 → 없음(무엇이 없는지 함께), 반영 → 들어감, 처리 → 구체 동사(확정, 취소, 저장), 기재 → 적음, 상이 → 다름.
5. **"및", "등", "~할 수 있습니다"를 줄인다.** "할 수 있습니다"는 실제로 고를 수 있는 선택지가 있을 때만.
6. **같은 화면에서 같은 말을 두 번 하지 않는다.** 카드 제목에 있는 말을 설명문 첫머리에서 되풀이하지 않는다.
7. **조건이 맞을 때만 보이는 안내는 조건이 맞을 때만 보인다.** 기록이 하나도 없는데 "요청은 선생님이 확인하면 확정으로 바뀝니다"를 띄우지 않는다.
8. **숫자는 아라비아 숫자.** "두 번" 대신 "2번", "세 과목" 대신 "3과목". 단 문장 속 관용구("한 번 더")는 예외.

## 3. 버튼

| 규칙 | 좋은 예 | 피할 예 |
| --- | --- | --- |
| **동사로 끝낸다** | 저장, 확정, 출석부 열기, 맞바꾸기 | 확인, OK, 다음 |
| 화면에 저장할 것이 **하나**면 동사만 | 저장 | 일지 저장(화면이 이미 일지 쓰기일 때) |
| 같은 화면에 저장할 것이 **둘 이상**이거나, **다른 화면으로 가는 버튼**(홈 카드)이면 대상 + 동사 | 일지 저장, 시간표 내기, 시설 일지 쓰기 | 저장(무엇을?), 이동 |
| 다른 화면으로 가는 버튼은 "~ 열기"·"~ 보기"·"~ 쓰기" | 출석부 열기, 내 OUT 자세히 보기 | 출석부, 바로가기 |
| "취소"는 두 뜻이 있으니 나눠 쓴다 | 시트 닫기: **돌아가기** / 기록을 취소 상태로: **취소 처리** | 취소(닫기인지 기록 취소인지 모름) |
| 뒤로 가기는 한 가지로 | ← 처음으로(홈으로), ← 돌아가기(같은 화면 안 한 단계 위) | 뒤로, 이전 화면, 홈 |
| 2~8자. 길면 대상을 줄인다 | 퇴실 확정 | 선택한 학생을 퇴실 확정하기 |

한 동작은 버튼 → 확인 시트 제목 → 결과 알림에서 **같은 낱말**로 부른다.
[퇴실 확정] → 시트 "퇴실 확정" → "퇴실을 확정했습니다."

## 4. 상황별 문구

### 4.1 오류

- **무엇이 → 어떻게 고치나**, 두 문장.
- 사과("죄송합니다")·탓("잘못 입력하셨습니다")·시스템 말("오류 500", "실패", "Exception")을 쓰지 않는다.
- 고칠 수 없는 오류(서버 문제)는 "다시 해 보고, 또 안 되면 누구에게"를 쓴다.

| 상황 | 좋은 예 |
| --- | --- |
| 입력 잘못 | "끝 날짜가 시작 날짜보다 앞입니다. 끝 날짜를 고쳐 주세요." |
| 빈 칸 | "학생을 고르세요" (X) → "학생을 골라 주세요." |
| 권한 없음 | "이 화면은 출결 담당 선생님만 고칠 수 있습니다. 바꿀 것이 있으면 출결 담당 선생님께 요청해 주세요." |
| 서버 문제 | "저장하지 못했습니다. 잠시 뒤 다시 눌러 보고, 또 안 되면 관리자 선생님께 알려 주세요." |
| 다른 사람이 먼저 고침 | "그사이 다른 선생님이 이 기록을 고쳤습니다. 새로 불러온 뒤 다시 저장해 주세요." |

### 4.2 빈 상태

- **한 줄 사실 + (있으면) 다음 행동.** 사실만으로 충분하면 한 줄로 끝낸다.
- 무엇이 없는지 정확히: "없습니다" (X) → "오늘 특이사항이 없습니다." (O)
- 학생·학부모 화면의 빈 상태는 안심을 주는 쪽으로: "이번 학기 OUT이 없습니다."

| 좋은 예 | |
| --- | --- |
| 오늘 특이사항이 없습니다. | 행동 필요 없음 |
| 아직 이번 기간 좌석을 배정하지 않았습니다. [좌석 배정 열기] | 다음 행동 있음 |
| 이 달에 등록된 일정이 없습니다. | |

### 4.3 확인 시트(되돌리기 어렵거나 여러 건을 바꾸는 동작)

- **제목** = 동작 이름(버튼과 같은 낱말). 질문형 "~할까요?"는 본문 끝 한 줄에만.
- **본문** = 무엇이 바뀌는지 숫자로 + 되돌릴 수 있는지.
- **버튼** = 같은 동작 이름 + [돌아가기].

```
퇴실 확정
1. 김가온 · 3월 31일(수)부터 퇴실
조식은 3월 31일(수)부터 멈추고, 석식은 4월 12일(월)부터 멈춥니다.
확정한 뒤에는 취소 처리로만 되돌릴 수 있습니다.
[퇴실 확정]  [돌아가기]
```

### 4.4 저장·결과 알림(토스트)

- 과거형 한 문장: "저장했습니다." / "3명을 확정했습니다."
- "저장되었습니다", "저장 완료", "성공적으로"는 쓰지 않는다.
- 부분 성공은 숫자로 나눠 말한다: "5명 중 4명을 옮겼습니다. 1명은 정원이 차서 옮기지 못했습니다."

### 4.5 불러오는 중

- "불러오는 중…" 하나로 통일. 오래 걸리는 작업만 무엇을 하는지 쓴다: "출석부를 만드는 중… (10초쯤 걸립니다)".

### 4.6 홈 카드 설명문

- 카드 제목 = 할 일이나 볼 것(명사구): "오늘 특이사항", "시설 일지".
- 설명 = **언제·왜 이 카드를 여는지** 한 문장. 기능 목록을 늘어놓지 않는다.
  - "특강실·원형테이블 같은 시설을 쓰면 근무 선생님께 말씀드린 뒤 여기에 적습니다." → 좋음(언제·왜).
- 숫자가 있으면 설명보다 숫자가 먼저: "확인 대기 3건".

## 6. 사람을 부르는 말

| 대상 | 화면에서 | 쓰지 않음 |
| --- | --- | --- |
| 교사(이름과 함께) | **이름 + 선생님**: "김하늘 선생님" | 이름 + 님("김하늘님"), 이름만 |
| 교사(역할로) | 담당 선생님, 담임 선생님, 근무 선생님, 출결 담당 선생님, 관리자 선생님 | 담당자, 담당교사님 |
| 교사(표 머리·라벨, 역할 이름) | 붙여 쓴다: **담당교사, 근무교사, 출결 담당, 관리자** | 담당 교사, 근무 교사(띄어 쓴 표 머리) |
| 학생(교사 화면) | "1. 김가온" | 김가온 학생(표 안), 학번 |
| 학생(학부모 화면) | 자녀 이름 그대로, 문장에서는 "자녀" | 귀 자녀, 학생 |
| 학생(학생 화면) | "내 ~": 내 OUT, 내 자리 | 학생님, 당신 |
| 학부모(교사 화면) | 학부모, 학부모 연락처 | 보호자(표에 섞어 쓰지 않는다. 연락처 표에서 '보호자 관계'처럼 꼭 필요한 곳만) |
| 학부모(학부모 화면 문장 속) | 학부모님 | 부모님, 보호자님 |

시험용 계정 이름에 직함이 들어 있으면("시험 학사교사") 화면이 "시험 학사교사님"처럼 어색해진다. **이름 칸에는 사람 이름만** 두고 직함은 역할로 보여 주자고 제안한다(가짜 데이터·계정 이름 정리는 코딩 세션 몫).

### 학부모 화면 표기

학부모는 앱 용어를 모른다. 학부모 화면에서는 다음처럼 풀어 쓴다.

| 저장 값 | 학부모 화면 |
| --- | --- |
| 기숙사: 입실 / 퇴실 / (기록 없음) | 기숙사: 입실 / 퇴실 / **신청 안 함** |
| 조식·중식: 실시 / 미실시 / (기록 없음) | 조식: 먹음 / **먹지 않음** / **신청 안 함** |
| 석식: 학사 석식 / 일반 석식 / 미실시 / (기록 없음) | 석식: 학사 석식 / 일반 석식 / **먹지 않음** / **신청 안 함** |
| 1OUT | OUT 1번 |
| 요청 / 확정 | 확인 중 / 확정 |

학생 화면도 같은 표기를 쓰되 "1OUT"은 학생이 익숙하므로 그대로 둔다.

## 8. 점검 순서(새 화면·문구를 쓸 때)

1. 누가 읽나(1절) → 어조·끝맺음을 고른다.
2. 버튼이 동사로 끝나나(3절).
3. 오류·빈 상태·확인 시트가 4절 틀을 따르나.
4. 날짜·시각·숫자가 5절 표기인가.
5. 사람 부르는 말·용어가 6·7절과 같나.
6. 조건이 맞을 때만 보이는 안내인가(2절 7번).
