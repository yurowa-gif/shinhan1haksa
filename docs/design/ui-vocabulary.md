# UI 용어집 — 선생님·AI·작업 세션이 같은 말로 화면을 부르기

> 2026-11-12 총괄. 바이브코딩 1주차 응용강의("함흥 Hero와 평양 UI", 2026-11-10)를 검토하고, 이 앱(Apps Script, 휴대폰 세로, 교사용 업무 화면)에 맞게 옮긴 것이다.
> 강의의 핵심 한 줄: **"예쁘게 해 줘"보다 이름을 불러 지시하면 AI가 정확히 만든다.** 이 앱은 이미 이름이 있는 부품(`UI.*`, `docs/design/components.md`)을 쓰므로, 일반 웹 용어와 우리 부품 이름을 짝지어 둔다.
> 디자인 규칙의 기준은 여전히 `docs/design/rules.md`(DESIGN 소유)다. 이 문서는 말을 맞추는 사전일 뿐 규칙을 바꾸지 않는다.

## 1. 일반 용어 ↔ 우리 앱

| 일반 웹 용어(강의) | 뜻 | 우리 앱에서 | 쓰는가 |
| --- | --- | --- | --- |
| 벤토 그리드(Bento Grid) | 크기가 다른 칸을 도시락처럼 배치 | 역할별 홈의 카드 묶음(`home_*.html`의 `.card`) | 일부. 360px에서는 한 줄 한 카드가 기본 — 넓은 화면에서만 2열 |
| 랜딩 페이지 / 히어로(Hero) | 첫 화면의 크게 눈길 끄는 영역 | 없음 | **쓰지 않는다.** 업무 앱은 첫 화면에 할 일이 바로 보여야 한다(홈 = 오늘 할 일 카드) |
| CTA(Call To Action) | 누르고 싶게 만든 주 버튼 | 아래 고정 바의 주 버튼(`UI.actionBar`, `.btn`) | 화면당 하나(rules 1절) |
| 내비게이션(GNB·LNB·SNB) | 사이트 전체·구역·옆 메뉴 | 홈 카드 → 화면, 화면 안에서는 `UI.segmented`(탭) | GNB·사이드바 없음(한 손, 좁은 화면) |
| 탭(Tabs) | 같은 자리에서 내용 바꾸기 / 다른 화면으로 가기 | 같은 자리: `UI.segmented`(예: 방 배정 / 정원 현황). 다른 화면으로 가는 위 탭: `.tabs`·`.tab`(예: OUT·입퇴실 화면 위 탭) | 씀 |
| 드롭다운(Dropdown) | 눌러서 고르는 목록 | 먼저 칩(`.chip`)·`segmented`, 많으면 `UI.studentPicker`(검색 선택) | 드롭다운은 마지막 수단(손가락으로 고르기 어려움) |
| 스티키(Sticky) / 픽스드(Fixed) | 스크롤해도 따라다니는 / 한자리에 고정 | 위 머리줄 `header.top`(스티키), 아래 바 `.actionbar`(픽스드) | 씀 |
| 브레드크럼(Breadcrumb) | 지금 위치·지나온 단계 표시 | 머리줄 왼쪽 `← 처음으로`(`.back`) + 화면 제목 | 한 단계만. 화면이 2단계 깊이를 넘지 않게 만든다 |
| 모달(Modal) / 라이트박스 | 뒤를 흐리고 띄우는 창 / 그 안에 사진·영상 | **바텀 시트** `UI.bottomSheet`·`UI.confirmSheet`(아래에서 올라옴) | 가운데 모달 대신 바텀 시트(엄지가 닿음) |
| 카드(Card) | 이미지·글을 묶은 네모 | `.card` | 씀 |
| 캐러셀(Carousel) | 옆으로 넘기는 카드 | 없음 | **쓰지 않는다.** 넘겨야 보이는 정보는 놓친다 |
| 푸터(Footer) | 맨 아래 정보(만든 이, 개인정보 처리방침) | 교사 화면엔 없음 | 학생·학부모 포털(F14)에는 개인정보 처리방침 링크 자리 필요 — 4단계에서 정함 |
| 토스트 | 잠깐 떴다 사라지는 알림 | `UI.toast` | 저장 결과 알림 |
| 빈 상태(Empty state) | 보여 줄 것이 없을 때의 안내 | `UI.emptyState` | 씀 |
| 상태 배지 | 짧은 상태 표시 | `UI.statusPill`, `UI.badge` | 색 + 글자 함께(색만으로 알리지 않음) |
| 테마 토큰 | 색·크기·모서리를 이름으로 모아 둔 값 | `Styles.html`의 `--accent`·`--tap` 등(rules 3절) | 화면마다 색을 따로 정하지 않는다 |

## 2. 선생님이 화면 고칠 것을 말할 때(예문)

강의에서 배운 순서대로 "**어느 화면 → 어느 부품 → 무엇을**"로 말하면 한 번에 알아듣는다.

- "좌석 화면 **아래 바**의 [저장] 버튼 글자를 '이대로 저장'으로 바꿔 줘."
- "방 배정 **확인 시트**에 '정원 초과 방 수'를 한 줄 더 보여 줘."
- "출결 담당 **홈 카드** 중 '오늘 특이사항'을 맨 위로 올려 줘."
- "급식 신청 화면의 **학년 칩** 옆에 반 칩도 넣어 줘."
- "**빈 상태** 문구를 '오늘은 정리할 특이사항이 없습니다'로 바꿔 줘."

화면 이름은 `docs/design/screens.md`, 부품 이름은 `docs/design/components.md`에 있다.

## 3. UI 프롬프트 틀(새 화면·큰 변경을 맡길 때)

강의 실습처럼 **구역마다 무엇을 넣을지** 적어 보내면 시안이 한 번에 가깝게 나온다. 빈칸만 채워 총괄에게 보내면 DESIGN·코딩 세션에 그대로 넘긴다.

```
[화면] 이름:            (예: 상담 신청 목록)   누가 쓰나: (역할)   언제·어디서: (예: 저녁 자습 중 휴대폰)
[목적] 이 화면에서 끝내야 할 일 한 가지:
[머리줄] 제목:           뒤로 가기: ← 처음으로
[위 안내] .notice에 넣을 한 줄(없으면 비움):
[본문 카드] 위에서부터 순서대로
  1. 카드:             들어갈 것:            고르는 방법(칩/검색 선택/날짜):
  2. 카드:
[탭] segmented가 필요하면 탭 이름들:
[아래 바] 주 버튼 하나:          보조 버튼:
[확인 시트] 저장 전에 보여 줄 줄들:     되돌릴 수 없으면 사유 입력: 예/아니오
[상태] 빈 상태 문구:      오류 때 문구:      불러오는 중 문구:
[권한] 이 화면을 못 보는 역할:     보이지만 못 고치는 역할:
[참고] 비슷한 기존 화면:          (사진·손그림이 있으면 함께)
[받을 것] 360px·1280px 시안 사진, 가짜 학생으로
```

지키는 규칙은 적지 않아도 된다(rules가 자동으로 붙는다): 360px 가로 스크롤 없음, 누르는 칸 48px, 주 버튼 하나는 아래 바, 색만으로 알리지 않음, 애니메이션 없음.

**채운 예:**
```
[화면] 이름: 2OUT 면담 기록   누가: 학사 교사(담당)   언제: 면담 직후 교무실 컴퓨터·휴대폰
[목적] 면담 날짜·참석자·합의 사항을 남긴다
[본문 카드] 1. 학생(검색 선택, 2OUT 대상만)  2. 면담 날짜(날짜 칸)·참석자(칩: 학부모/학생/담임)  3. 합의 사항(글 입력, 3줄 이상)
[아래 바] 주 버튼: 면담 기록 저장   보조: 비우기
[확인 시트] "학생 ○○ · 11월 12일 면담 · 참석 학부모·학생" + "저장하면 관리자가 퇴실을 확정할 수 있습니다"
[상태] 빈 상태: "지금 2OUT 대상 학생이 없습니다"
[권한] 못 보는 역할: 담임·출결 담당·학생·학부모
```

## 4. 강의에서 가져오지 않는 것과 이유

| 강의 내용 | 이 앱에서 | 이유 |
| --- | --- | --- |
| React·Tailwind·shadcn/ui("평양 UI") | 쓰지 않는다. **같은 생각을 이미 쓰고 있다**: 공통 부품 `UI.*` + 테마 토큰 = 우리 앱의 평양 UI | Apps Script `HtmlService`에는 빌드 단계가 없고, CLAUDE.md "새 외부 라이브러리는 넣지 않는다" |
| tweakcn으로 테마 변주 | 색·크기를 바꿀 때는 `Styles.html` 토큰만 바꾼다(한 군데 → 전체) | 같은 원리. 대비 4.5:1 검사(`tests/design/styles.test.js`)를 통과해야 한다 |
| 21st.dev 히어로·애니메이션·영상 히어로·스크롤 저항 | 쓰지 않는다 | rules 1절 "애니메이션·깜박임 없음", 저녁 자습 중 한 손 업무 화면 |
| 눈누 한글 웹폰트 | 지금은 기기 기본 글꼴(아래 4절) | 학교 와이파이·데이터에서 글꼴 내려받기 지연, 폰트마다 웹 임베딩 허용이 다름 |

## 5. 외부 디자인 자료를 참고할 때(검증해 보니 강의와 다른 점)

- **라이선스 표시가 없는 코드는 쓰지 않는다.** 강의는 "없어도 대체로 괜찮다"고 했지만, 저작권은 표시가 없으면 **모든 권리가 만든 사람에게** 있다(GitHub 문서·choosealicense.com). 강의의 최종 권고("가급적 라이선스 있는 것만")가 맞다.
- **MIT·Apache도 '아무 조건 없음'은 아니다.** 저작권·라이선스 고지를 함께 남겨야 하고(Apache는 바꾼 곳 표시도) — 이 앱은 코드를 가져오지 않으므로 해당 없음. 화면 **모양을 참고**하는 것은 괜찮다.
- **폰트는 '상업용 무료'와 '웹 임베딩 허용'이 다르다.** 눈누에서도 폰트마다 제작사 약관이 다르므로 '임베딩' 항목을 따로 확인한다. OFL은 대부분 허용하지만 고친 폰트에도 OFL을 다시 붙여야 한다.
- 지금 `Styles.html`의 첫 글꼴 `Pretendard`는 **불러오는 코드가 없다**. 그래서 실제로는 휴대폰 기본 한글 글꼴(안드로이드 Noto Sans 계열, 아이폰 Apple SD 고딕)이 나온다. 의도된 선택인지 DESIGN이 확인해 rules에 적는다(불러온다면 OFL·임베딩 확인 + 실제 배포에서 로딩 시간 측정).
- **이미지 만들기:** 강의의 `$imagen`은 ChatGPT 채팅 문법이 아니라 Codex의 `$imagegen` 스킬 호출로 보인다(공식 문서 확인 필요). 이 프로젝트에서는 디자인 시안 그림이 필요할 때 선생님 요청대로 GPT 이미지 모델을 쓴다. Claude는 그림 파일을 직접 만들지 못하지만 SVG·HTML 시안은 만든다.
