# D15 2단계 ② — 반응형·마우스·키보드 (휴대폰 3종 + 노트북 3종)

> 선생님 말씀(총괄 전달): "자료 조사해서 디자이너들 레퍼런스 참고 좀 해서 만들면 좋겠다. 노트북 윈도우 크롬창으로도 잘 열리고 휴대폰 안드로이드나 아이폰에서도 잘 운용이 되어야 해. **색 타령만 하지 말고.**"
> 이 PR은 색이 아니라 **배치·반응형**입니다. 근거는 `docs/design/references.md` 0절 다섯 가지와 `docs/design/device-compat.md`입니다. 사진은 실제 `src/ui` 화면을 가짜 서버에 띄워 찍었습니다(`node design/preview/refresh-responsive.js before|after`). 이름·숫자는 모두 가짜, 가짜 오늘 2027-03-26.

## 4. 점검

| 점검 | 결과 |
| --- | --- |
| 기기 행렬(`npm run devices -- --base=docs/design/devices-baseline.json`, 31화면 × 8기기) | **나빠진 칸 0**, 좋아진 칸 24(홈의 "처음으로·접속 진단" 48px, 글자 150% 넘침 2곳) + 출석부 미리보기 포커스 8칸(`sheet`)은 이 PR에서 해결 |
| 사진 48장(8화면 × 6기기) 가로 넘침 | 없음 |
| 대비 4.5:1 | 색 토큰은 그대로라 `styles.test.js`가 계속 지킴 |
| 누르는 칸 | 줄 높이는 건드리지 않음(48px 유지) |

**남은 기기 행렬 실패(PR ③에서):** 일정 요일 칸(작은칸 7)·좌석 층·성별(작은칸 5)·담임 홈 이름 링크(작은칸 2)·식수 집계 마지막 링크(150% 가림)·입퇴실·일괄 퇴실(150% 가림)·시설 일지 150%. 출석부 미리보기 포커스는 해결했다.

## 5. 마우스 환경에서 누르는 칸 40px을 허용할지 — 제안(미적용)

`rules.md` 2-1절에 근거와 함께 적었다. 요약: WCAG 2.2는 대상 크기 최소 24px(AA)이고 48px은 터치 기준이다. 그러나 학교 노트북은 터치 화면일 수 있어 `pointer: fine`만으로 판정하기 어렵고, 기기 행렬 도구와 `styles.test.js`가 48px로 검사한다. **줄 높이를 줄이고 싶으면 누르는 칸 높이는 두고 줄 사이 여백만** 줄인다. 선생님 결정이 나면 `--tap`을 `@media (pointer: fine)`에서만 바꾼다.

## 6. 건너뛴 것·확인 못 한 것

- **실제 윈도우 노트북(맑은 고딕)·실제 아이폰 Safari·카카오톡 인앱 브라우저는 못 봤다.** 사진은 크로미움(이 환경의 한국어 글꼴)이라 글자 모양이 윈도우와 다르다. 아이폰 칸은 크기·터치만 흉내 낸 것이다.
- **왼쪽 레일은 "역할 전환"뿐이다.** 기능 메뉴(출석부·좌석표 등)를 왼쪽에 늘어놓는 구조는 만들지 않았다(홈의 참고 열이 그 역할). 선생님이 원하시면 후속.
- **목록 + 옆 상세 두 칸(레퍼런스 ⑦)은 만들지 않았다.** OUT·특이사항·입퇴실 화면은 PR ③.
- **Enter로 저장:** 입력 칸이 `<form>`이 아니라 Enter가 저장하지 않는다(Esc 닫기는 있음). 바꾸려면 화면 코드를 고쳐야 해서 PR ③ 후보.
- **타이포 4단계(27/20/18/15)**는 지금 5단계(27/20/18/16/14)라 PR ③에서 화면과 함께 정리한다(`rules.md` 2-1절).
- 키보드가 올라올 때 아래 바(아이폰)는 시트 안 버튼이 흐름 맨 아래라 괜찮지만, **화면에 직접 고정된 아래 바(`.actionbar`)가 아이폰 키보드에 가려지는지는 실기기 확인이 필요**하다.
- **나머지 `screen_*`(약 30개)의 눈 점검은 PR ③.**
