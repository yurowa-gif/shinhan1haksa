# 화면 글 전수 점검표

> 2026-11-20 자료조사 세션(W1). 기준은 `docs/design/writing.md`(말투 가이드).
> **문서만 바꾼다.** 실제 고치기는 디자인 새 단장(D15) 뒤 코딩 세션이 이 표를 보고 한다. 시트에 저장되는 값(`docs/contracts/vocabulary.md`)은 바꾸지 않고 화면 표시만 바꾼다.
> 범위: `src/ui/*.html` 전부(개발용 `screen_printspike.html`·`Diag.html` 제외)와 `src/features/*.gs`·`src/Code.gs`·`src/Auth.gs`에서 사용자에게 보이는 문구. 행 번호는 main `1e1d04e` 기준.

## 읽는 법

- **우선순위** — 상: 틀린 정보를 주거나 사용자가 막히는 글(특히 학생·학부모 화면). 중: 용어·어조가 다른 화면과 어긋나거나 눈에 띄게 어색함. 하: 다듬기.
- **이유** — 장황 / 모호 / 용어 불일치 / 어조 / 정보 누락 / 조건 안 맞음 / 형식. 괄호 속 숫자는 `writing.md`의 절.
- `{변수}`는 화면에서 값이 들어가는 자리. 표의 이름은 모두 가짜 이름이다.
- 같은 문제가 여러 곳이면 먼저 **1절(한 번에 고치는 곳)**을 하고, 남은 행을 6절 표에서 고친다.

## 3. 정해야 할 것

- OUT 화면 탭 이름: 안내문은 **[퇴실 대상]**, 탭은 **[2OUT]**(`screen_moves.html:349·495`, `screen_outs.html:240`). 하나로 정한다 — 제안: **퇴실 대상**(학생·학부모 화면과 같은 말).
- 미리 확인하는 버튼 이름: 명단은 **확인**(`screen_roster.html:70`), 좌석·운영 기간은 **미리보기**, 일정은 **미리 보기**. 제안: **미리 보기**(띄어 씀, 표준 표기)로 통일.
- `docs/design/rules.md` 5절 "문구"는 `writing.md`로 옮기고 연결 한 줄만 남긴다(DESIGN 소유 문서라 DESIGN·총괄 결정).
- 시험 계정 이름에 직함이 들어 있어("시험 학사교사") "시험 학사교사님"처럼 보인다. 이름 칸에는 사람 이름만 두자(가짜 데이터 정리, 코딩 세션).
- 역할 이름 "근무표 담당자"(`src/Schema.gs:21`, 화면에 그대로 나옴) → "근무표 담당". 저장 값이 아니라 표시용 이름인지 코딩 세션이 확인한다.
