# 2단계 선생님 확인 체크리스트 (초안)

> 이 문서는 `docs/plan/stage2.md` 6절(확인 묶음)을 선생님이 따라 하기 쉬운 순서로 풀어 쓴 **초안**입니다. 화면 이름과 버튼 이름은 `docs/design/screens.md`와 D6 시안 기준이라, 실제 화면에서 다르면 그 기능을 만든 PR이 이 문서를 같이 고칩니다. 사진 자리는 비워 두었고 확인할 때 채웁니다.
> 출력물(근무 기록표·식수 집계)을 종이로 볼 때의 자세한 항목은 `docs/design/print-check.md` 9·10절입니다.

## 읽는 법

- 한 단계 = **누르는 것 → 이렇게 보이면 통과 → 사진 → 결과(○/×)** 입니다.
- **누가** 칸: **소유자**는 선생님(앱 주인, 스크립트 편집기를 쓸 수 있는 계정), **시험1**·**시험2**는 아래 시험 계정, **아무 교사**는 편집기 없이 휴대폰에서 화면만 누르면 되는 일입니다. 나중에 다른 선생님(학사 교사 6~8명)께 부탁할 때는 **아무 교사** 단계만 드리면 됩니다.
- ×가 나오면 **번호 + 한 줄**(예: "B5 막히지 않고 저장됨")과 화면 사진을 총괄에게 보냅니다. 앱이 이상한 것이지 선생님이 잘못 누르신 것이 아닙니다.
- 컴퓨터 테스트(`npm test`)가 이미 확인한 것은 "이미 확인됨"으로 적었습니다. 여기서는 **실제 Apps Script에서만 보이는 것**(로그인, 메일, PDF, 휴대폰 화면, 속도)만 봅니다.
- 이름은 모두 **가짜 데이터**입니다. 실제 학생 이름을 쓰는 시험은 없습니다.

## B. 근무표·교대 (②, 약 25분)

### 준비 (소유자, 한 번만)

1. 편집기에서 시험1 계정을 등록합니다: `addUser(시험1 gmail, '시험교사', 'hall_teacher,duty_manager')`. 시험2 계정도 같은 방식으로 `attendance` 역할로 등록합니다.
2. `clasp push`로 새 코드를 올리고 **setup을 다시 실행**합니다. 로그에 `[탭 생성]`, `[열 추가]`가 보이면 됩니다(이미 있으면 "변경 없음").
3. 앱이 권한을 다시 요청하면 **승인**합니다(메일 보내기 권한이 새로 들어갑니다).
4. 프로젝트 설정의 스크립트 속성에 `MAIL_ENABLED`를 `true`로 둡니다. 메일은 시험 gmail 주소로만 가고, 가짜 이름의 example.com 주소로는 가지 않습니다.
5. 스크립트 속성 `TEST_TEACHER_EMAIL`을 **1번에서 등록한 시험1 gmail과 같은 주소**로 둡니다(가짜 근무표가 이 계정을 근무자로 넣습니다).
6. 편집기에서 가짜 데이터를 넣습니다: `seedFakeStage2`(두 번 실행해도 중복되지 않습니다). 1월에 확인한다면 가짜 교대가 있는 1/5·1/13·1/23은 피해서 확인합니다. "가짜 학생(seedFakeData)만 있는 DB에서만…"으로 거부되면(1단계 확인 때 명단을 올려 진짜 모양 학생이 생긴 경우) 새 시험 데이터 파일에서 setup → seedFakeData → seedFakeStage1 → seedFakeStage2 순서로 다시 합니다(안전장치는 넓히지 않습니다).

## C. OUT·면담·퇴실 (③a, 약 40분)

| 번호 | 누가 | 누르는 것 | 이렇게 보이면 통과 | 사진 | 결과 |

| C6 | 담당교사 | 메일함을 봅니다(담당교사·담임) | OUT 메일이 오고 **학생 이름·상황 메모가 없다**(날짜·항목·몇 OUT인지·앱 링크만) | | |

| C11 | 소유자 | 유형(학사 퇴실 등)과 석식을 고르고 [입퇴실 신청] → 확인창에서 저장 | 확인창 맨 위에 **"3월 ○일(요일)부터 …퇴실"** 처럼 날짜가 크게 보이고 아래에 자리 공석·조식 중단일·석식 중단일이 나온다. 저장하면 퇴실 대상 카드가 "퇴실 처리됨"이 된다 | | |
| C12 | 아무 교사 | 학사생이 아닌 계정·담임 계정으로 퇴실 확정 버튼을 찾아봅니다 | 버튼이 없거나 눌러도 "권한이 없습니다"가 나온다 | | |
| C13 | 소유자 | 홈(관리자)을 엽니다 | 화면이 3초 안에 열린다(느리면 응답에 나오는 시간 값을 총괄에게 알린다). "퇴실 대상 N명 / 면담 필요 / 확정 가능"이 현재 상태와 같다 | | |

> 컴퓨터 테스트가 이미 확인한 것: 2OUT 판정, 면담 없이는 퇴실 확정이 막히는 규칙, 연결된 OUT이 취소되면 면담이 다시 필요한 규칙, 권한 밖 학생 거부, 메일에 이름이 없는 것, 메일이 실패해도 OUT은 저장되는 것.
