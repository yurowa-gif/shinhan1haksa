# 화면 와이어프레임 (D2)

순서: **C5(F1 특이사항)** → **C7(F2 출석부)** → **C6(F5 좌석)** → C1·C3·C4. 코딩 세션이 해당 PR을 만들 때 이 문서와 `docs/design/rules.md`(규칙)·`docs/design/components.md`(`UI.*`)를 따른다. 이미 만든 화면(C1·C3·C4)은 맨 아래 "고칠 점"으로 정리했다.

## 읽는 법

- 와이어프레임은 휴대폰 **세로 360px** 기준이다. 글씨 크기·색은 토큰이 정하므로 그리지 않는다. `[ 버튼 ]` `( 칩 )` `(•) 선택됨` `▼ 고르기` `{입력}`.
- `UI.이름`은 공통 컴포넌트, `.이름`은 `Styles.html` 클래스다. 화면 안에서 새로 `local…` 컴포넌트를 만들기 전에 이 목록에 있는지 본다.
- **탭 수**는 손가락으로 누르는 횟수이고, 글자 입력은 따로 센다(키보드가 올라오는 입력 1회 = "입력 1").
- 모든 화면 공통: 위 `← 처음으로` + 제목, 본문은 `.card`, 핵심 동작은 아래 `.actionbar`(`UI.actionBar`)에 둔다. 오류·빈 상태 문구는 rules.md 5절을 따른다.
- 권한은 서버가 정한다. 화면은 역할에 따라 **보이는 버튼만 다르게** 할 뿐 보안이 아니다(CLAUDE.md 3번).

## 1. 홈 카드 배치 (역할별)

홈은 "오늘 할 일"을 위에서 아래로. 카드는 눌러서 그 화면으로 간다(카드 전체가 48px 이상 높이의 누르는 칸). 숫자는 `UI.badge`.

### 출결 담당 (`attendance`)

```
┌ 신한1학사 · 출결 담당 ──────┐
│ 오늘 3월 3일(수)            │
│ 2027 1학기 · 학사생 30명     │
├────────────────────────────┤
│ ① 오늘 출석부                │  ← 큰 카드, 누르면 F2 화면 (홈→1탭)
│   PDF로 열기                 │
├────────────────────────────┤
│ ② 특이사항 요청  (3)          │  ← 담임·담당교사 요청 배지, 0이면 배지 없음
│   확정할 요청이 있습니다       │
├────────────────────────────┤
│ ③ 오늘·내일 특이사항           │
│   오늘 5명 · 내일 2명         │
│   [ 특이사항 입력 ]           │
├────────────────────────────┤
│ ④ 격자 정리 남은 날짜 (F11)    │  ← 5단계. 지금은 "5단계에서 만듭니다" soon 카드
└────────────────────────────┘
```

순서 이유: 근무 시간 직전에 가장 많이 하는 일이 출석부 열기, 그다음이 요청 확정, 그다음 입력.

### 학사 교사 (`hall_teacher`)

```
│ 오늘 3월 3일(수) · 내 근무: 21:30조 │  ← 근무표 전(1단계)에는 "근무 정보는 2단계"
├────────────────────────────┤
│ ① 오늘 출석부                │  ← 열기만(F2). 읽기 전용
├────────────────────────────┤
│ ② 내가 보낸 요청 처리 상태     │
│   ◔ 요청 2 · ✓ 확정 5 · ⊘ 취소 1 │  ← UI.statusPill 세 개
│   [ 요청 보내기 ]              │  ← 내 담당 학생에게만(F1)
├────────────────────────────┤
│ ③ 내 담당 학생 (12명)          │  ← 목록 보기 → 학생별 특이사항 열람
│ ④ 서류 미제출·OUT 알림         │  ← 2단계 soon 카드
```

학사 교사는 특이사항을 **직접 확정하지 않고 요청**만 한다(출결 담당이 확정).

### 담임 (`homeroom`)

```
│ 2-3 학사생 (14명)            │
│  ( 모두 )( 요청 중 )          │  ← UI.segmented, 기본 모두
│  1. 김가온  ·  ◔ 요청 1       │  ← 이름 옆 상태 pill, 누르면 학생 기록 보기
│  2. 이나래                    │
│ [ 특이사항 요청 ]             │  ← 우리 반 학생에게만
```

### 관리자 (`admin`)

1단계 홈은 기존 "전체 현황"에 카드 세 장을 더한다: 운영 기간(C1), 명단 올리기(C3), 자습 일정·블록(C4). 출석부·좌석 카드도 같은 줄에 둔다. 2단계 항목은 soon 카드로 둔다.

## 2. C5 — F1 사전 특이사항

### 2-1. 입력 화면 (30초 흐름)

출결 담당이 학생 한 명의 하루 특이사항을 넣는 경로. **홈 카드 "특이사항 입력" 탭 1회**에서 시작해 저장까지 **탭 4회 + 입력 1회(이름 초성 2~3자)**, 약 20~30초.

```
← 처음으로   특이사항 입력
┌ 학생 ──────────────────────┐
│ {ㄱㄱㅇ                  }  │  ← UI.studentPicker, 키보드 자동 열림 (입력 1회)
│ ┌ 1. 김가온   1-3 5번 ┐      │
│ ┌ 1. 김가을   1-3 6번 ┐      │  ← 결과 1탭 = ① 학생 선택 (탭 1)
└────────────────────────────┘
┌ 언제 ──────────────────────┐
│ [ 하루 | 기간 ]               │  ← UI.segmented, 기본 "하루"
│ 3월 3일(수)  ( 오늘 )( 내일 ) │  ← UI.dateField, 기본 오늘 → 대부분 손대지 않음(탭 0)
└────────────────────────────┘
┌ 어느 시간 ─────────────────┐
│ (•전체)( 18–20 )( 20–22 )( 22–24 ) │  ← UI.blockChips, 기본 전체 (탭 0)
│ ( 15:00 부터 귀가 )  {15:00}  │  ← 칩을 누르면 시각 입력. 15:00–24:00으로 저장
└────────────────────────────┘
┌ 유형 ──────────────────────┐
│ ( 병결 )( 병지각 )( 병조퇴 )  │  ← 자주 쓰는 유형을 맨 위 칩으로. 선택(탭 2)
│ ( 가정사유 )( 학원 )( 외부 )    │     (칩 줄 아래 "더 보기"로 나머지 유형)
│ ( 내부 )( 무지 )( 무조 )( 무결 )( 기타 ) │
│ ⚠ 미인정 유형입니다. 1OUT 예정 │  ← 무지·무조·무결을 고르면 .notice.warn
├────────────────────────────┤
│ 메모(선택) {                } │  ← 건강 정보는 길게 쓰지 않는다는 힌트(.hint)
└────────────────────────────┘
[ 닫기 ]            [ 저장 ]     ← .actionbar, 저장 (탭 3)... 학생 선택(1)+유형(2)+저장(3)=3탭, 날짜·블록을 바꾸면 +1~2
```

- 저장하면 **바로 확정**되고(출결 담당) toast "저장했습니다." + 폼이 비워지며 학생 칸에 다시 포커스(같은 날 여러 명 연속 입력). "방금 저장: 1. 김가온 · 병결 · 3월 3일(수)" 한 줄을 폼 위에 남긴다(`.notice.ok`).
- **기간**(예: 가족여행 3월 3일(수)–3월 5일(금))은 `UI.rangeField`. 날짜마다 1행으로 저장되고 같은 묶음(`group_id`)이다. 저장 전에 "3일 · 3월 3일(수)–3월 5일(금)"을 확인 줄로 보여 준다.
- 같은 학생·날짜·시간에 이미 확정된 특이사항이 있으면 저장 전에 `.notice.warn`: "이 시간에 이미 병결이 있습니다. 그래도 저장하면 두 건이 됩니다."(칸에는 최근 것 + "외 1"로 나온다).
- 오류 예: "학생을 골라 주세요.", "유형을 골라 주세요.", "종료일이 시작일보다 빠릅니다. 종료일을 같은 날이나 뒤로 고쳐 주세요."
- 미인정 유형은 **자동 1OUT이 2단계(F4)에서 연결**되므로(plan 5절) 1단계에서는 "1OUT 예정" 표시만 한다. 문구에서 "자동으로 1OUT이 만들어집니다"라고 약속하지 않는다.

### 2-2. 요청 입력 (학사 교사·담임)

같은 화면에서 학생 선택이 **내 담당 학생·우리 반 학생으로 제한**되고, 아래 바의 주 버튼이 `[ 요청 보내기 ]`, 안내 줄에 "출결 담당 선생님이 확인하면 출석부에 반영됩니다."를 둔다. 유형 칩에서 미인정 유형도 요청할 수 있다. 서버가 범위 밖 학생을 거부하면 "권한이 없습니다. 내 담당 학생(또는 우리 반 학생)만 요청할 수 있습니다."

### 2-3. 요청 처리 (출결 담당)

```
← 처음으로   특이사항 요청 (3)
┌ 3월 3일(수) 병결 · 18–20 ─────┐
│ 1. 김가온 · 요청: 박선생(담임)  │  ← 이름+유형+요청자. 메모는 접어 두고 "메모 보기"
│ ◔ 요청                        │  ← statusPill
│ [ 취소 처리 ]   [ 확정 ]       │  ← 48px 두 버튼. 취소 = UI.confirmWithReason("사유")
└────────────────────────────┘
```

- 확정하면 `✓ 확정`으로 바뀌고 목록에서 접힌다(탭 1). 취소 사유는 요청한 교사에게 보인다.
- 요청이 하나도 없으면 `UI.emptyState("처리할 요청이 없습니다.")`.

### 2-4. 오늘·내일 / 학생별 목록

- **오늘·내일:** `UI.segmented`(오늘 | 내일 | 이번 주), 각 줄 = "1. 김가온 · 병결 · 18–20 · ✓ 확정", 줄을 누르면 상세(수정·취소 처리). 상단에 "오늘 5명" 합계.
- **학생별 누적:** 학생 선택 후 날짜 역순 목록. `취소`된 것은 `⊘ 취소`(취소선)로 남고 사유가 보인다(기록은 지우지 않는다).
- 취소 처리는 `UI.confirmWithReason`(rules.md 6절), 확정된 건의 수정은 "취소 처리 후 다시 입력"으로 단순하게 시작한다.

## 3. C7 — F2 출석부 PDF

### 3-1. "버튼 두 번" 경로

**홈 → 오늘 출석부(탭 1) → PDF 열기(탭 2).** 두 번째 화면은 열리자마자 오늘 날짜의 미리보기를 자동으로 보여 주므로 따로 "만들기"를 누르지 않는다.

```
← 처음으로   출석부
┌ 3월 3일(수) ──────────────────┐
│ [ ‹ ]   2027년 3월 3일(수)  [ › ]│  ← 하루씩 이동(48px). 날짜를 누르면 UI.dateField
│ 2027 1학기 · 월~목 · 3개 블록     │
├────────────────────────────┤
│ ( 1층 자습실 )( SA1 )( SA2 )…   │  ← 공간 탭(칩, 가로 스크롤 허용 상자). 기본 1층
│ ┌────────────────────────┐ │
│ │ (미리보기: iframe srcdoc)    │ │  ← printRenderSheet_ 가 만든 HTML. 작게 축소 표시
│ └────────────────────────┘ │
│ ⚠ 칸 높이를 줄여 빠듯합니다     │  ← printSheetPlan_ 경고가 있을 때만
└────────────────────────────┘
[ 닫기 ]            [ PDF 열기 ]
```

- 운영 안 하는 날: 미리보기 대신 `UI.emptyState("3월 7일(일)은 운영하지 않는 날입니다.")`, 주 버튼은 꺼짐(`disabled`)이고 이유를 같이 쓴다.
- 좌석 배치가 없는 기간이면 `.notice.warn` "이 기간 좌석 배치가 없습니다. 좌석 배치 화면에서 먼저 배정해 주세요."(모델 `warnings`).
- 근무 이름이 비어 있으면 "근무 이름은 아직 비어 있습니다. 인쇄한 뒤 손으로 적어 주세요."(`.hint`, 2단계 근무표 전까지).
- PDF 만드는 중: 버튼 `disabled` + "PDF를 만드는 중… (10초 안에 끝납니다)". 실패하면 `.error` "PDF를 만들지 못했습니다. 다시 눌러 주세요. 계속 안 되면 미리보기 화면을 인쇄해 주세요."(C0 결과에 따라 문구 조정).
- 보이는 역할: 관리자·출결 담당·학사 교사. 담임·학생·학부모에게는 홈 카드가 없다.

### 3-2. 확인
미리보기는 확인용이고, 정확한 모양은 PDF로 본다. PDF를 기존 출석부와 맞춰 보는 항목은 `docs/design/print-check.md`.

## 4. C6 — F5 좌석 배치 (PC 권장)

PRD 8절: 좌석·방 배치 화면만 PC를 권장한다. 휴대폰에서도 동작하지만 `.notice.info`로 "넓은 화면(PC)에서 편합니다."를 안내한다. 칸은 48px 이상으로 유지하고 격자가 넓으면 **상자 안에서만** 가로로 민다(`UI.seatGrid`).

### 4-1. 공간·격자 그리기 (관리자)

```
← 처음으로   좌석 배치
┌ 공간 ──────────────────────┐
│ ( 1층 자습실 )( SA1 )…( + 공간 추가 ) │  ← 칩
│ [ 칸 그리기 ]   [ 배정하기 ]    │  ← UI.segmented 두 모드
├────────────────────────────┤
│ 칸을 누를 때마다 좌석 → 기둥 → 비상문 → 창문 → 빈칸 순서로 바뀝니다. │ ← .hint
│ ┌ 격자(1층 20×12) ──────┐ │
│ │ ▢▢ . ▢▢ ▢▢ . …            │ │  ← seatGrid 'single' 모드 + 칸 종류 표시
│ └────────────────────────┘ │
│ [ 표 붙여넣기로 가져오기 ]     │  ← 시트 좌석표 복사 → parseSeatGridTsv_
└────────────────────────────┘
```

### 4-2. 배정(교사·관리자)

```
┌ 기간: 2027 1학기 ───────────┐
│ 배정 안 된 학생 (4명)          │
│ ( 모두 )( 남 )( 여 )( 1학년 )( 베리타스 ) │  ← UI.blockChips 스타일 칩 필터
│  3. 박다솜       ▸             │  ← 학생을 누르고 → 자리 칸을 누르면 배정 (탭 2)
│ ┌ 격자 ────────────────────┐ │
│ │ 1. 김가온 | 2. 이나래 | 공석 …│ │  ← 이름은 "1. 이름", 빈 자리는 "공석"
│ └────────────────────────┘ │
│ 두 자리를 차례로 누르면 맞바꿉니다. │ ← seatGrid 'swap' 모드
└────────────────────────────┘
```

- 학생을 고르고 빈 자리를 누르면 즉시 배정, 이미 학생이 있는 자리를 누르면 `UI.confirmSheet`("1. 김가온과 2. 이나래의 자리를 맞바꿉니다.", [취소] [맞바꾸기]).
- 한 락 안의 두 행 수정이므로 저장 실패 시 `.error` "자리를 바꾸지 못했습니다. 화면을 새로 불러온 뒤 다시 눌러 주세요."
- 규칙 위반 빨간 표시와 자동 초안 만들기는 3단계(이 화면에는 비활성 soon 카드).
- 권한: 학사 교사·관리자는 작성, 담임·출결 담당은 보기(출결 담당 작성 여부는 CODING 권한표를 따른다).

## 5. 이미 만든 화면 — C1·C3·C4의 고칠 점

D1~D3가 병합된 뒤 코딩 세션이 다음 PR에서 반영한다(기능 변경 없음, 규칙 맞추기).

| 화면 | 고칠 점 |
| --- | --- |
| C1 운영 기간 | `localField` → `UI.field`(오류는 `setError`). 저장 버튼을 아래 `.actionbar`로 옮기고 `main.has-actionbar`. 현재 기간 표시 `term-tag` → `UI.statusPill('confirmed', '현재')` 대신 `.pill.mute`. 날짜가 겹치는 경고는 `.notice.warn` |

| C4 자습 일정 | 월 달력의 날짜 칸을 48px 이상으로, 날짜를 누르면 `UI.bottomSheet`(운영 여부 `UI.segmented`, 시작·종료 시각, 메모). "운영 안 함"으로 바꾸기는 `UI.confirmSheet`("그날 출석부가 사라집니다."). 되돌리기는 "취소 처리"(기록은 남음) |
| 공통 | 홈의 `.btn` 카드 링크 높이 48px 이상 확인. 화면 틀 `screen_shell.html`의 뒤로 링크는 공통 `.back`을 쓴다 |
