# 화면 와이어프레임 (D2)

순서: **C5(F1 특이사항)** → **C7(F2 출석부)** → **C6(F5 좌석)** → C1·C3·C4. 코딩 세션이 해당 PR을 만들 때 이 문서와 `docs/design/rules.md`(규칙)·`docs/design/components.md`(`UI.*`)를 따른다. 이미 만든 화면(C1·C3·C4)은 맨 아래 "고칠 점"으로 정리했다.

## 읽는 법

- 와이어프레임은 휴대폰 **세로 360px** 기준이다. 글씨 크기·색은 토큰이 정하므로 그리지 않는다. `[ 버튼 ]` `( 칩 )` `(•) 선택됨` `▼ 고르기` `{입력}`.
- `UI.이름`은 공통 컴포넌트, `.이름`은 `Styles.html` 클래스다. 화면 안에서 새로 `local…` 컴포넌트를 만들기 전에 이 목록에 있는지 본다.
- **탭 수**는 손가락으로 누르는 횟수이고, 글자 입력은 따로 센다(키보드가 올라오는 입력 1회 = "입력 1").
- 모든 화면 공통: 위 `← 처음으로` + 제목, 본문은 `.card`, 핵심 동작은 아래 `.actionbar`(`UI.actionBar`)에 둔다. 오류·빈 상태 문구는 rules.md 5절을 따른다.
- 권한은 서버가 정한다. 화면은 역할에 따라 **보이는 버튼만 다르게** 할 뿐 보안이 아니다(CLAUDE.md 3번).

## 1. 홈 카드 배치 (역할별)

홈은 "오늘 할 일"을 위에서 아래로. 카드는 눌러서 그 화면으로 간다(카드 전체가 48px 이상 높이의 누르는 칸). 숫자는 `UI.badge`.

### 출결 담당 (`attendance`)

```
┌ 신한1학사 · 출결 담당 ──────┐
│ 오늘 3월 3일(수)            │
│ 2027 1학기 · 학사생 30명     │
├────────────────────────────┤
│ ① 오늘 출석부                │  ← 큰 카드, 누르면 F2 화면 (홈→1탭)
│   PDF로 열기                 │
├────────────────────────────┤
│ ② 특이사항 요청  (3)          │  ← 담임·담당교사 요청 배지, 0이면 배지 없음
│   확정할 요청이 있습니다       │
├────────────────────────────┤
│ ③ 오늘·내일 특이사항           │
│   오늘 5명 · 내일 2명         │
│   [ 특이사항 입력 ]           │
├────────────────────────────┤
│ ④ 격자 정리 남은 날짜 (F11)    │  ← 5단계. 지금은 "5단계에서 만듭니다" soon 카드
└────────────────────────────┘
```

순서 이유: 근무 시간 직전에 가장 많이 하는 일이 출석부 열기, 그다음이 요청 확정, 그다음 입력.

### 학사 교사 (`hall_teacher`)

```
│ 오늘 3월 3일(수)                │
│  ● 내 근무  21:30조 (21:30까지)  │  ← 근무가 없으면 "오늘은 근무가 없습니다". 예비 감독이면 "예비 감독"
│  다음 근무: 3월 6일(토) 근무     │
│  [ 내 근무 교대 ]                │
├────────────────────────────┤
│ 서류 미제출  … 2건              │  ← 입퇴실·급식 기록 중 서류 미제출(대표 행만 센다)
├────────────────────────────┤
│ 내 담당 학생 OUT                │
│  ▲ 1OUT 1명  ⛔ 퇴실 대상 1명    │  ← 퇴실 대상에 면담 기록이 없으면 [면담 기록하러 가기]
├────────────────────────────┤
│ OUT 기록  [ OUT 기록하기 ]       │
│ 출석부 · 내가 보낸 요청 · 담당 학생 │  ← 1단계 카드 그대로
```

2단계 시안: `design/preview/out/stage2/home-hall-*.png`. 학사 교사는 특이사항을 **직접 확정하지 않고 요청**만 한다(출결 담당이 확정).

### 근무표 담당자 (`duty_manager`)

```
│ 3월 근무표                      │
│  [ 2 ]빈 날  [ 3 ]이번 달 교대   │  ← .stat 두 칸
│  비어 있는 날: 3월 3일(수) 23:00조, 3월 7일(일) 예비 감독

│ 교대 이력 · 월말 근무 기록표 (엑셀) · 출석부 │  ← 기록표 카드 [근무 기록표 열기]
```

시안: `home-duty-*.png`.

### 담임 (`homeroom`)

```
│ 2-3 학사생 (14명)            │
│  ( 모두 )( 요청 중 )          │  ← UI.segmented, 기본 모두
```


기숙사 정원 대비 공석은 3단계(F8)에서 넣는다.

## 2. C5 — F1 사전 특이사항

### 2-1. 입력 화면 (30초 흐름)

출결 담당이 학생 한 명의 하루 특이사항을 넣는 경로. **홈 카드 "특이사항 입력" 탭 1회**에서 시작해 저장까지 **탭 4회 + 입력 1회(이름 초성 2~3자)**, 약 20~30초.

```
← 처음으로   특이사항 입력
┌ 학생 ──────────────────────┐
│ {ㄱㄱㅇ                  }  │  ← UI.studentPicker, 키보드 자동 열림 (입력 1회)
│ ┌ 1. 김가온   1-3 5번 ┐      │
│ ┌ 1. 김가을   1-3 6번 ┐      │  ← 결과 1탭 = ① 학생 선택 (탭 1)
└────────────────────────────┘
┌ 언제 ──────────────────────┐
│ [ 하루 | 기간 ]               │  ← UI.segmented, 기본 "하루"
│ 3월 3일(수)  ( 오늘 )( 내일 ) │  ← UI.dateField, 기본 오늘 → 대부분 손대지 않음(탭 0)
└────────────────────────────┘
┌ 어느 시간 ─────────────────┐
│ (•전체)( 18–20 )( 20–22 )( 22–24 ) │  ← UI.blockChips, 기본 전체 (탭 0)
│ ( 15:00 부터 귀가 )  {15:00}  │  ← 칩을 누르면 시각 입력. 15:00–24:00으로 저장
└────────────────────────────┘
┌ 유형 ──────────────────────┐
│ ( 병결 )( 병지각 )( 병조퇴 )  │  ← 자주 쓰는 유형을 맨 위 칩으로. 선택(탭 2)
│ ( 가정사유 )( 학원 )( 외부 )    │     (칩 줄 아래 "더 보기"로 나머지 유형)
│ ( 내부 )( 무지 )( 무조 )( 무결 )( 기타 ) │
│ ⚠ 미인정 유형입니다. 1OUT 예정 │  ← 무지·무조·무결을 고르면 .notice.warn. C12(자동 1OUT 연결) 병합 때부터 "저장하면 1OUT이 기록됩니다"(요청 화면은 "확정되면 1OUT이 기록됩니다")로 바꾼다
├────────────────────────────┤
│ 메모(선택) {                } │  ← 건강 정보는 길게 쓰지 않는다는 힌트(.hint)
└────────────────────────────┘
[ 닫기 ]            [ 저장 ]     ← .actionbar, 저장 (탭 3)... 학생 선택(1)+유형(2)+저장(3)=3탭, 날짜·블록을 바꾸면 +1~2
```

- 저장하면 **바로 확정**되고(출결 담당) toast "저장했습니다." + 폼이 비워지며 학생 칸에 다시 포커스(같은 날 여러 명 연속 입력). "방금 저장: 1. 김가온 · 병결 · 3월 3일(수)" 한 줄을 폼 위에 남긴다(`.notice.ok`).
- **기간**(예: 가족여행 3월 3일(수)–3월 5일(금))은 `UI.rangeField`. 날짜마다 1행으로 저장되고 같은 묶음(`group_id`)이다. 저장 전에 "3일 · 3월 3일(수)–3월 5일(금)"을 확인 줄로 보여 준다.
- 같은 학생·날짜·시간에 이미 확정된 특이사항이 있으면 저장 전에 `.notice.warn`: "이 시간에 이미 병결이 있습니다. 그래도 저장하면 두 건이 됩니다."(칸에는 최근 것 + "외 1"로 나온다).
- 오류 예: "학생을 골라 주세요.", "유형을 골라 주세요.", "종료일이 시작일보다 빠릅니다. 종료일을 같은 날이나 뒤로 고쳐 주세요."
- 미인정 유형(무지·무조·무결)은 **저장(확정)하는 순간 F4 자동 1OUT이 기록된다**(2단계 C12 병합 때부터). **C12가 병합되기 전에는 "1OUT 예정"만 쓰고**(약속하지 않는다), 병합 뒤 입력 화면은 "저장하면 1OUT이 기록됩니다", 요청 화면(학사 교사·담임)은 "확정되면 1OUT이 기록됩니다"라고 쓴다. 취소하면 그 OUT도 함께 취소된다는 안내를 취소 확인창에 붙인다.

### 2-2. 요청 입력 (학사 교사·담임)

같은 화면에서 학생 선택이 **내 담당 학생·우리 반 학생으로 제한**되고, 아래 바의 주 버튼이 `[ 요청 보내기 ]`, 안내 줄에 "출결 담당 선생님이 확인하면 출석부에 반영됩니다."를 둔다. 유형 칩에서 미인정 유형도 요청할 수 있다. 서버가 범위 밖 학생을 거부하면 "권한이 없습니다. 내 담당 학생(또는 우리 반 학생)만 요청할 수 있습니다."

### 2-3. 요청 처리 (출결 담당)

```
← 처음으로   특이사항 요청 (3)
┌ 3월 3일(수) 병결 · 18–20 ─────┐
│ 1. 김가온 · 요청: 박선생(담임)  │  ← 이름+유형+요청자. 메모는 접어 두고 "메모 보기"
│ ◔ 요청                        │  ← statusPill
│ [ 취소 처리 ]   [ 확정 ]       │  ← 48px 두 버튼. 취소 = UI.confirmWithReason("사유")
└────────────────────────────┘
```

- 확정하면 `✓ 확정`으로 바뀌고 목록에서 접힌다(탭 1). 취소 사유는 요청한 교사에게 보인다.
- 요청이 하나도 없으면 `UI.emptyState("처리할 요청이 없습니다.")`.

### 2-4. 오늘·내일 / 학생별 목록

- **오늘·내일:** `UI.segmented`(오늘 | 내일 | 이번 주), 각 줄 = "1. 김가온 · 병결 · 18–20 · ✓ 확정", 줄을 누르면 상세(수정·취소 처리). 상단에 "오늘 5명" 합계.
- **학생별 누적:** 학생 선택 후 날짜 역순 목록. `취소`된 것은 `⊘ 취소`(취소선)로 남고 사유가 보인다(기록은 지우지 않는다).
- 취소 처리는 `UI.confirmWithReason`(rules.md 6절), 확정된 건의 수정은 "취소 처리 후 다시 입력"으로 단순하게 시작한다.

## 3. C7 — F2 출석부 PDF

### 3-1. "버튼 두 번" 경로

**홈 → 오늘 출석부(탭 1) → PDF 열기(탭 2).** 두 번째 화면은 열리자마자 오늘 날짜의 미리보기를 자동으로 보여 주므로 따로 "만들기"를 누르지 않는다.

```
← 처음으로   출석부
┌ 3월 3일(수) ──────────────────┐
│ [ ‹ ]   2027년 3월 3일(수)  [ › ]│  ← 하루씩 이동(48px). 날짜를 누르면 UI.dateField
│ 2027 1학기 · 월~목 · 3개 블록     │
├────────────────────────────┤
│ ( 1층 자습실 )( SA1 )( SA2 )…   │  ← 공간 탭(칩, 가로 스크롤 허용 상자). 기본 1층
│ ┌────────────────────────┐ │
│ │ (미리보기: iframe srcdoc)    │ │  ← printRenderSheet_ 가 만든 HTML. 작게 축소 표시
│ └────────────────────────┘ │
│ ⚠ 칸 높이를 줄여 빠듯합니다     │  ← printSheetPlan_ 경고가 있을 때만
└────────────────────────────┘
[ 닫기 ]            [ PDF 열기 ]
```

- 운영 안 하는 날: 미리보기 대신 `UI.emptyState("3월 7일(일)은 운영하지 않는 날입니다.")`, 주 버튼은 꺼짐(`disabled`)이고 이유를 같이 쓴다.
- 좌석 배치가 없는 기간이면 `.notice.warn` "이 기간 좌석 배치가 없습니다. 좌석 배치 화면에서 먼저 배정해 주세요."(모델 `warnings`).
- 근무 이름이 비어 있으면 "근무 이름은 아직 비어 있습니다. 인쇄한 뒤 손으로 적어 주세요."(`.hint`, 2단계 근무표 전까지).
- PDF 만드는 중: 버튼 `disabled` + "PDF를 만드는 중… (10초 안에 끝납니다)". 실패하면 `.error` "PDF를 만들지 못했습니다. 다시 눌러 주세요. 계속 안 되면 미리보기 화면을 인쇄해 주세요."(C0 결과에 따라 문구 조정).
- 보이는 역할: 관리자·출결 담당·학사 교사. 담임·학생·학부모에게는 홈 카드가 없다.

### 3-2. 확인
미리보기는 확인용이고, 정확한 모양은 PDF로 본다. PDF를 기존 출석부와 맞춰 보는 항목은 `docs/design/print-check.md`.

## 4. C6 — F5 좌석 배치 (PC 권장)

PRD 8절: 좌석·방 배치 화면만 PC를 권장한다. 휴대폰에서도 동작하지만 `.notice.info`로 "넓은 화면(PC)에서 편합니다."를 안내한다. 칸은 48px 이상으로 유지하고 격자가 넓으면 **상자 안에서만** 가로로 민다(`UI.seatGrid`).

### 4-1. 공간·격자 그리기 (관리자)

```
← 처음으로   좌석 배치
┌ 공간 ──────────────────────┐
│ ( 1층 자습실 )( SA1 )…( + 공간 추가 ) │  ← 칩
│ [ 칸 그리기 ]   [ 배정하기 ]    │  ← UI.segmented 두 모드
├────────────────────────────┤
│ 칸을 누를 때마다 좌석 → 기둥 → 비상문 → 창문 → 빈칸 순서로 바뀝니다. │ ← .hint
│ ┌ 격자(1층 20×12) ──────┐ │
│ │ ▢▢ . ▢▢ ▢▢ . …            │ │  ← seatGrid 'single' 모드 + 칸 종류 표시
│ └────────────────────────┘ │
│ [ 표 붙여넣기로 가져오기 ]     │  ← 시트 좌석표 복사 → parseSeatGridTsv_
└────────────────────────────┘
```

### 4-2. 배정(교사·관리자)


### F6-1. 입퇴실 (학사 교사·관리자)

시안: `moves-inout`·`moves-confirm`·`moves-prefill`. 화면 탭: **입퇴실 · 급식 변경 · 학생 기록**(PRD 메뉴 하나).

```
학생: {ㅂㄷㅅ} → 3. 박다솜     지금 상태: 학사 · 기숙사 · 조식 실시 · 석식 학사 석식
무엇을: ( 학사 퇴실 ✕ ) ( 기숙사 퇴실 ) (•학사 및 기숙사 퇴실 )   ← 셋을 따로 보인다. 기숙사생의 "학사 퇴실"은 꺼 두고 안내(결정 50)
신청 일시: 3월 3일(수) 10:45               ← 기본 지금(미래 일시·날짜만은 막음)
적용일: 3월 5일(금)  ( 오늘 )( 내일 )       ← UI.dateField
급식 정리  석식: ( 중단 | 일반 석식으로 )    ← 학사 퇴실일 때만. 조식은 퇴실일부터 바로 중단(.notice.info)
사유 {   }  ☐ 학교 서류 제출함 ⚠ 서류 미제출로 기록됩니다
[ 닫기 ]            [ 입퇴실 신청 ]
```

- 유형은 **학사 퇴실 / 기숙사 퇴실 / 학사 및 기숙사 퇴실**을 따로 보이고(입실 유형은 입실할 수 있는 학생에게만), **기숙사생의 "학사 퇴실" 칩은 꺼 두고** `.hint` "기숙사생은 '학사 퇴실'만 할 수 없습니다. '학사 및 기숙사 퇴실'로 신청해 주세요."를 보인다(결정 50). 기숙사 입실은 "조식도 입실일부터", 기숙사 퇴실은 "조식도 미실시".
- **2OUT 퇴실 확정 뒤 미리 채운 신청서**(`moves-prefill`): 학생(퇴실 확정 화면과 같은 학생)·적용일(**확정한 다음 날**, 고칠 수 있음)·사유 "2OUT 퇴실"·서류 미제출은 채우고, **유형과 석식은 미리 고르지 않는다**. 둘 다 `.field.invalid` + `.fix`("유형을 골라 주세요."·"석식을 골라 주세요. 기본값이 없습니다.")로 보이고, 고르지 않으면 저장되지 않는다. **필수 오류가 남아 있는 동안 아래 [입퇴실 신청] 버튼은 꺼 둔다**(급식 변경 화면과 같음). 면담 날짜·내용은 넣지 않는다.
- **확인창(날짜를 크게)**: `UI.confirmSheet` lead **"3월 5일(금)부터 학사 및 기숙사 퇴실"**, 줄 "자리 공석 / 기숙사 3월 5일 퇴실 / 조식 3월 5일 중단 / 석식 3월 15일(월) 중단 / 서류 미제출로 기록됩니다". 지난 날짜면 "지난 출석부·식수가 바뀝니다" 줄을 더한다. 되돌릴 수 없는 일이라 `danger`.
- 서류 미제출은 담당교사 홈 카드와 식수 집계 아래 "서류 미제출 N명 ▸"에 남는다(적용은 한다).

### F7-1. 급식 변경 신청 (담당교사·관리자)

시안: `meal-change`·`meal-change-edit`·`meal-confirm`.

```
학생: {ㄱㄱㅇ} → 1. 김가온
무엇을: ( 조식 실시 )( 조식 미실시 )( 석식 실시 )( 석식 미실시 )( 일반 석식으로 변경 )

  ⓘ 수~일 신청이라 다다음 주 월요일부터 적용됩니다.     ← 이유 한 줄(.notice.info)
```

- 문구 규칙(rules.md 6절): 적용일과 이유를 한 줄로. 예) 3월 3일(수) 신청·석식 미실시 → "3월 15일(월)부터 석식이 미실시로 바뀝니다. 수~일 신청이라 다다음 주 월요일부터 적용됩니다.", 3월 3일(수) 10:45 신청·석식 실시 → "오늘(3월 3일)부터 적용됩니다. 11:30 전 신청입니다."
- 잘못 넣은 신청을 되돌리는 버튼은 2단계에 없다(새 신청으로 바로잡는다, plan 4-2).

### F5-3. 좌석 초안 만들기 → 미리보기 → 저장

```
좌석 초안
┌ 21 바뀌는 자리 ┐┌ 5 규칙 위반 ┐          ← .stats
⚠ 베리타스 3명은 SA실이 모자라 1층 자습실로 배정했습니다.   ← .notice.warn (넘칠 때만)

│ 2   ⚠3   4 …        │ │ ⚠ 11번 · 같은 학년 · 옆 2. 정하나 │  ← 줄을 누르면 그 칸으로 이동
```

- 진입: 배정 모드 아래 바의 [초안 만들기](`seat-assign`). 누르면 **지금 배정을 바꾸지 않고** 미리보기를 연다(`seat-draft-preview`). 저장 전에는 어디에도 쓰지 않는다.
- 숫자 두 개: "바뀌는 자리 N개"(지금 배정과 다른 자리 수), "규칙 위반 M개"(위반 칸 수 — 서버 `violations[]` 한 건이 칸 한 개. 같은 학년 둘이 붙으면 두 칸이 각각 센다).
- 빨간 칸: `UI.seatGrid`의 칸 `bad:true`(`.seat-cell.bad`) — **굵은 빨간 테두리 + 번호 앞 ⚠ + 읽어 주는 말 "(규칙 위반)"**. 색만으로 알리지 않는다. 위반 목록의 줄(`.chip.bad`)도 같은 모양이다.
- 위반 종류 3가지(R14): `같은 학년`(앞뒤·좌우 이웃, 기둥·비상문은 이웃을 끊음), `떨어뜨릴 짝`(범위 좌석·둘 다), `성별`(구역). 각 줄은 "번호 · 종류 · 설명".
- 위반 목록 줄을 누르면 그 칸이 골라진 모양(파란 바깥 테두리)으로 보이고 격자가 그 칸으로 스크롤한다. (목록 → 칸 한 방향만이다.)
- 저장: 아래 바 [저장] → `confirmSheet`(`seat-draft-save`): lead "바뀌는 자리 21개 · 규칙 위반 5개", lines "규칙 위반이 있어도 저장할 수 있습니다." "지금 배정은 기준일 전날까지로 끝나고, 지난 날짜 출석부·좌석표는 그대로 남습니다". **[저장]은 위반 때문에 꺼지지 않는다.** 서버는 지금 배정 끝내기 + 새 배정을 한 락에서 쓴다(C22). 두 번 눌러도 한 벌.
- [취소]는 미리보기만 닫는다(아무것도 안 바뀜).
- 3학년 전 자리 유지·베리타스 SA실 우선 같은 규칙은 서버(R14)가 정하고, 화면은 결과와 경고(`.notice.warn`)만 보여 준다. "베리타스는 희망 시 1층"은 저장하지 않으므로 초안 뒤 맞바꾸기로 한다.
- 담임(`seat-homeroom`): 열람만. 격자에 `같은 학년`·`성별` 빨간 표시는 있어도 **떨어뜨릴 짝은 표시도 목록 줄도 없고** 서버 응답에도 없다. [초안 만들기]·[저장]·맞바꾸기 버튼이 없다.
- 관리자·학사 교사의 짝 줄에는 상대 이름이 보이고(예 "짝: 3. 배승우"), 사유는 짝 관리 화면에서만 본다.

### F5-4. 떨어뜨릴 짝 관리 (관리자·학사 교사)

- 목록(`pair-list`): "A ↔ B", 범위(좌석·방·둘 다), 사유. 칩 [유효 N][취소 포함 N]으로 거른다. 줄마다 [취소] 버튼. **삭제 버튼은 없다.** 취소하면 줄이 "취소됨"(`statusPill` `canceled`)으로 남고 누가·언제 취소했는지 `audit_log`에 남는다(`pair-cancel` 확인창, 위험 색).
- 안내(`.notice.info`): "사유는 관리자·학사 교사만 봅니다." 그리고 어떤 범위가 어디에 쓰이는지 한 줄.
- 추가(`pair-add`): 학생 두 명(`UI.studentPicker` 두 개), 범위 `UI.segmented`(좌석·방·둘 다), 사유(짧게, 입력 `hint` "관리자·학사 교사만 봅니다"). [짝 추가]는 두 학생이 같거나 이미 같은 짝이 있으면 `.error`.
- 담임·학생·학부모에게는 이 화면도 홈 카드도 없고 짝·사유가 어떤 응답에도 들어가지 않는다(결정 64).

### F8-1. 방 배정 (관리자·학사 교사)

```
방 배정                        2027 1학기 · 기숙 24명(남 16·여 8)
( 3층 남 )( 4층 남 )( 5층 여 )( 6층 여 )( 7층 여 )   ← 층 칩
┌ 3층 1호  남 · 4/4명 ┐ ┌ 3층 2호 …┐ ┌ 3층 3호 …┐   ← PC: 3열, 휴대폰: 1열
│ (1. 김가온)(2. 박도윤)  │
│ (3. 이서준)(1. 최하준)  │
└────────────────────┘
[ 초안 만들기 ]  [ 방으로 옮기기 ]            ← 아래 바 (옮기기는 학생을 고르면 켜짐)
```

- 층 칩 = 층 + 성별(층의 성별은 고정). 방 카드 안 학생은 "학년. 이름" 칩(`.chip`, 48px). 빈 자리는 `disabled` 칩 "빈 자리".
- 맞바꾸기: 학생 두 명을 차례로 누르면 `confirmSheet`(`room-swap-confirm`, lead "3층 1호 1. 김가온 ⇄ 3층 4호 3. 황민석"). 옮기기: 학생 한 명을 고르고 [방으로 옮기기] → 방 고르기 시트(`room-move-sheet`, 같은 층의 방과 남은 자리). 정원이 찬 방도 고를 수 있고 "⚠ 정원 초과"로 알린다(고르는 것은 막지 않지만, 그대로는 저장할 수 없다).
- 규칙 위반(`room-edit`): **정원 초과**(5/4: 카드 빨간 테두리 + "정원 초과" 알약(`out2`) + `.error` 줄)와 **떨어뜨릴 짝이 같은 방**(카드 빨간 테두리 + 두 학생 칩 `.chip.bad` + `.error` 줄). 맨 아래 "규칙 위반 N개" 목록. **정원 초과·성별 불일치가 하나라도 있으면 [저장]이 꺼지고**(`disabled`) 이유를 `.error`로 알린다("정원 초과가 있어 저장할 수 없습니다. …"). 같은 학년·떨어뜨릴 짝만 있으면 저장할 수 있다(표시만).
- [초안 만들기](`room-draft-preview`): "바뀌는 학생 N명 · 규칙 위반 M개". 위반이 0이면 `.notice.ok` "규칙 위반이 없습니다". 저장 전에는 쓰지 않는다. 저장하면 지금 배정은 기준일 전날까지로 끝나고 새 배정이 생기며, 지난 날짜 기록은 그대로 남는다(좌석과 같은 방식, 학기마다 전체 다시 배정).
- 학년은 방마다 섞이도록 그렸다. 층을 채우는 순서(낮은 층부터인지)는 R15가 정한다 — 시안은 낮은 층부터 채운 모습이다.

### F8-2. 정원 현황판

- 표(`room-stats`): 행은 층(3층 남 … 7층 여) + 남 합계·여 합계·전체, 열은 정원·입실·빈 자리·1학년·2학년·3학년(학년은 입실 인원). 합계 줄은 굵은 글씨 + 회색 바탕(`table.data` `tr.total`). 휴대폰에서는 표 안에서만 가로로 밀고 첫 열은 고정.
- 정원은 결정 24: **남 48(12실×4) · 여 92(23실×4)**, 층별 3층 16 · 4층 32 · 5층 28 · 6층 32 · 7층 32. 시안의 입실 24명(남 16·여 8)은 홈 시안(`home-admin`)의 가짜 숫자와 같다.
- 홈 카드(`home-admin-dorm`): 남·여 빈 자리와 [정원 현황판 열기]. 관리자·학사 교사 홈에 얹는다(C23).
- 보는 사람: 관리자·학사 교사·출결 담당·근무표 담당자(`room.view`). 방 배정을 바꾸는 것은 관리자·학사 교사(`room.edit`), 방 구성(층·호실·정원) 편집은 관리자(`room.layout`).

### 5-3 가정·확인 못 한 것

- `// ASSUMPTION` 규칙 위반 개수는 **칸(또는 학생·방) 단위**로 센다. 같은 학년 둘이 붙으면 2개.
- 시안은 1층 자습실 한 공간만 그렸다. SA실·성별 구역 표시는 같은 방식이고 시안 범위 밖이다.
- 방 초안이 정원 초과·짝 위반을 낼 수 있는지(불가능한 입력)는 R15 결과를 본 뒤 `room-draft-preview`에 경고 문구를 맞춘다. 초안은 정원·성별을 지켜 만들어지므로 [저장]이 꺼지는 경우는 손으로 고친 뒤(`room-edit`)다.
