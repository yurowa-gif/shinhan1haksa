# Anthropic `frontend-design` 가이드 검토 — 우리 앱에 가져올 것 / 가져오지 않을 것 (D13)

> 2026-11-19 디자인 세션. 선생님 요청: Anthropic 공식 `frontend-design` 가이드를 읽고 우리 앱에 맞게 정리한다. **코드를 복사하지 않고 원칙만** 옮긴다.
> 결론은 6절 "rules.md 반영 제안"이고, 반영한 내용은 PR 설명의 "계약 변경"에 적었다(규칙 변경이므로 총괄이 보고 병합).

## 1. 무엇을 읽었나

- 출처: 공개 저장소 `anthropics/skills`의 `skills/frontend-design/SKILL.md`(9,390자, 2026-11-19에 `git clone --depth 1`로 받음).
- 라이선스: 같은 폴더의 `LICENSE.txt` — **Apache License 2.0**(파일 머리에서 확인). `SKILL.md` 머리말도 "Complete terms in LICENSE.txt"라고 적혀 있다. 우리는 가이드의 **원칙을 우리 말로 요약**했을 뿐 문장·코드를 옮기지 않았으므로 이 저장소에 라이선스 파일을 들여오지 않는다(요약에 출처만 적는다). 나중에 문장을 그대로 쓰게 되면 Apache 2.0 고지(원 저작권·라이선스 사본·변경 표시)를 함께 둬야 한다.
- 가이드가 말하는 것(한 문단): "디자인 스튜디오의 리드처럼, 템플릿 같지 않은 **뚜렷한 시각 정체성**을 만들어라. 주제·대상·핵심 일에서 출발하고, 서체를 신중히 고르고, 구조 장치(테두리·번호·구분선)에는 뜻을 담고, 움직임은 아껴라. '크림색 바탕 + 세리프 + 테라코타', '검정 + 산성 초록', '신문형', '같은 카드 반복', '템플릿 장식(대문자 라벨·점으로 이은 메타·→)'은 **AI가 만든 티가 나는 기본값**이니 의식적으로 피해라. 글(카피)은 사용자 눈높이로, 능동태로, 같은 동작은 같은 이름으로, 오류는 사과하지 말고 방법을 말하고, 빈 화면은 다음 할 일을 알려라. 먼저 계획(색·글자·배치·원칙)을 짜고 점검한 뒤 만들고, 대담함은 한 곳에만 쓰고, 반응형·키보드 포커스·접근성은 기본으로 지켜라."

## 2. 우리 앱의 조건(이 조건이 판정의 기준)

| 조건 | 내용 |
| --- | --- |
| 일 | 출결·근무·기숙사·급식·상담 **업무 화면**. 교사가 저녁 자습 중 서서 한 손으로 30초 안에 끝내야 한다. 학생·학부모는 **처음 쓰는 사람**이 많다 |
| 기기 | 휴대폰 세로(360px) 우선, 격자·표만 PC |
| 기술 | Apps Script(`HtmlService`). **외부 라이브러리·웹폰트·애니메이션 없음**, 실시간 없음(`docs/design/rules.md` 1·3절) |
| 접근성 | 글자 대비 4.5:1(`tests/design/styles.test.js`가 검사), 누르는 칸 48px, 색만으로 뜻을 전하지 않음 |
| 일관성 | 여러 선생님이 매일 같은 화면을 반복한다. **배우기 쉬움 = 같은 모양이 같은 뜻**이 정체성보다 앞선다. 상태 색은 뜻이 고정돼 있다(확정 초록·요청 노랑·취소 회색…) |

## 3. 항목별 판정

판정: **가져온다**(그대로) / **바꿔 가져온다**(우리 조건에 맞게) / **가져오지 않는다**.

| # | 가이드의 원칙 | 판정 | 이유와 우리 규칙에서의 모양 |
| --- | --- | --- | --- |
| 1 | 주제·대상·핵심 일에서 출발한다 | **바꿔 가져온다** | 시안을 그리기 전에 "누가 쓰나 · 이 화면의 일 한 가지 · 가장 눈에 띄어야 할 것 하나"를 한 줄씩 적는다(rules.md 8절). 이미 있는 "제목은 하는 일로"와 같은 정신. 이번 학생·학부모 시안(D13)에서 처음 적용 |
| 2 | 뚜렷한 시각 정체성·미학적 모험·"남과 다른 룩" | **가져오지 않는다** | 업무 앱이라 정체성보다 **일관성**이 일이다. 색은 상태의 뜻(확정·요청·취소·OUT)에 고정돼 있어 장식으로 바꿀 수 없다. 모험은 선생님이 화면을 배우는 비용이 된다 |
| 3 | 서체를 신중히 고르고(다른 두 서체 조합, 표제 서체) 글자 단계를 정한다 | **일부만(단계 + 굵기)** | 서체는 **고를 수 없다**(웹폰트 금지 결정, rules.md 3절). 대신 가이드의 "명확한 글자 단계와 의도한 굵기"는 이미 토큰(`--font-base` `--font-sm` `--font-lg` `--font-xl`)으로 있고, 굵기는 제목·상태에만 쓴다. 새로 할 것 없음 |
| 4 | 한 줄 80자 미만 | **이미 지킨다** | 휴대폰은 360px, PC 본문은 `main` 최대 720px(rules.md 2절). 격자·표는 예외 |
| 5 | 피할 글자 습관: 제목의 한 단어만 색·굵게, 대문자 라벨, 불필요한 작은 라벨 줄 | **가져온다** | 대문자는 한글이라 해당 없음. **한 단어만 강조**하지 않는다(강조는 상태 알약·경고 상자처럼 뜻이 있는 곳에만). **카드 제목 바로 아래 같은 말을 되풀이하는 작은 설명 줄은 줄인다**(예: 제목 "상담일지" 아래 "상담일지를 봅니다"). rules.md 8절 점검표에 넣는다 |
| 6 | 구조 장치(번호·구분선·테두리)는 뜻이 있을 때만 | **가져온다** | 우리 "색 + 모양 + 낱말" 원칙과 같다. 추가: **번호는 순서가 있는 내용에만**(시간표 제출 단계처럼). 장식 번호 금지(8절) |
| 7 | 움직임은 아껴라, 사용자 행동에 답하는 움직임은 환영 | **가져오지 않는다**(규칙 유지) | 우리는 애니메이션 자체가 없다(실시간·무한 스크롤도 없음). 시트가 아래에서 올라오는 것까지만. `prefers-reduced-motion`을 따로 챙길 일이 없다 |
| 8 | 글(카피): 사용자 눈높이, 능동태, **같은 동작은 같은 이름**, 오류는 사과 없이 방법을 | **가져온다** | rules.md 5절 "문구"와 90% 같다. 새로 더할 것: ① **한 동작의 이름을 끝까지 같게**(버튼 [저장] → "저장했습니다." 처럼 버튼·알림·시트 제목이 같은 낱말), ② **오류에 사과하지 않는다**("죄송합니다" 금지, 무엇이·어떻게), ③ **학생·학부모 화면은 학교 말이 아니라 쉬운 말**(예: "퇴실 대상" 옆에 뜻을 한 줄) |
| 9 | 빈 화면은 다음 할 일을 알려 준다 | **이미 있다** | rules.md 5절 "빈 상태". 학부모 첫 화면(연결된 자녀 없음)에 처음 적용해 본다(D13 시안 `parent-home-nolink`) |
| 10 | "AI 티 나는 기본값" 목록 | **점검표로만 가져온다** | 크림 + 세리프 + 테라코타, 검정 + 산성 초록, 신문형, 그라데이션 장식은 우리 팔레트·서체와 **원래 다르다**(해당 없음). 해당되는 것은 ① **무게가 다른 정보를 같은 카드로 줄줄이 나열**, ② **점(·)으로 이은 긴 한 줄**(예: "대상 학생 · 박선생 · 학부모에게 …"), ③ 모든 링크 끝의 "→". → 8절 점검표 3줄 |
| 11 | 첫 화면(히어로)은 그 주제에서 가장 특징적인 것 | **바꿔 가져온다** | 우리는 히어로를 쓰지 않는다(ui-vocabulary.md). 대신 **홈의 맨 위는 "지금 내가 해야 할 일 한 가지"**(학생: 퇴실 대상 안내·시간표 제출 마감, 학부모: 동의 요청). 큰 숫자 + 작은 라벨 + 그라데이션은 가이드도 기본값이라 하니 홈 카드에 장식으로 쓰지 않는다 |
| 12 | 두 번에 걸쳐 일한다: 계획(토큰·ASCII 배치) → 점검 → 만들기 | **바꿔 가져온다** | 토큰은 이미 `Styles.html`에 있다. 배치 계획만 가져온다: 시안 전에 ASCII 와이어프레임 한 장(screens.md 방식 그대로). 점검은 8절 점검표 |
| 13 | 절제: 대담함은 한 곳, 하나만 기억에 남게 | **바꿔 가져온다** | "한 화면에서 강하게 보이는 것은 하나"로 바꾼다 — 우리는 "주 버튼은 화면당 하나"(rules.md 1절)와 같은 정신이라 **강한 색 상자(경고·퇴실 대상)도 한 화면에 하나**로 못 박는다(8절) |
| 14 | 품질 바닥: 반응형·키보드 포커스·접근성·스크린샷으로 점검 | **이미 있다** | `--focus`, 48px, 4.5:1, 360·1280 스크린샷 점검(`design/preview/*.js`). 새로 더할 것 **하나**: 학생·학부모는 큰 글씨 설정을 쓰는 가족이 많을 것이므로 시안 점검에 **기기 글자 크기를 키운 모양**(예: 글자 150%)을 한 번 본다(8절) |
| 15 | "의뢰인이 이미 거절한 틀에 박힌 제안을 피하라" | **가져오지 않는다** | 의뢰인(선생님)이 원하는 것은 틀에 박힌 **일관된** 화면이다 |

## 4. 우리 화면에서 점검해 본 것(실제로 걸리는 곳)

가이드의 점검표(10번)를 지금 있는 화면에 대 보았다.

- **점(·)으로 이은 긴 줄**이 가장 많다: 상담 목록 "대상 학생 · 박선생 · 학부모에게 날짜·교사 보임", OUT 목록 "가장 최근: …". 교사 화면에서는 한눈에 훑는 용도라 두고, **학생·학부모 화면에서는 줄을 나누거나 낱말 하나로** 쓴다(D13 시안이 그렇게 그렸다).
- **같은 무게 카드 나열**: 교사 홈은 일부러 그렇다(할 일 카드가 많고 서로 같은 급). 학생·학부모 홈은 카드가 적으므로 맨 위 "해야 할 일" 한 칸만 강하게 보이게 한다.
- **카드 제목 아래 되풀이 설명**은 몇 곳 있으나 뜻을 더하는 곳(예: 서류 체크리스트의 "학기 초 서류를 냈는지 표시합니다")이라 그대로 둔다. 고칠 곳이 있으면 화면 PR에서 코딩 세션이 줄인다(이 PR은 화면 코드를 고치지 않는다).

## 5. 가져오지 않기로 한 것의 짧은 요약

정체성·모험적 미학(2, 15), 서체 선택(3), 움직임(7). 이유는 한 줄로 **업무 앱의 일관성·접근성·기술 제약**이다.

## 6. rules.md 반영 제안(이 PR에서 `docs/design/rules.md`에 반영함 — 규칙 변경)

| 위치 | 바꾼 것 |
| --- | --- |
| 1절 표 | 행 추가 **"학생·학부모 화면"**: 처음 쓰는 사람 기준. 학교 말(퇴실 대상·OUT)에는 뜻을 한 줄 붙인다. 점(·)으로 이은 긴 줄 대신 줄을 나눈다. 홈 맨 위는 "지금 해야 할 일" 한 칸 |
| 5절 표 | 행 추가 **"한 동작의 이름"**(버튼·알림·시트 제목이 같은 낱말), **"오류에 사과하지 않는다"** |
| 새 8절 | **"화면을 그리기 전 한 줄 계획과 점검"**: 계획 3줄(누가 · 이 화면의 일 한 가지 · 가장 눈에 띌 것 하나) + 점검 6줄(무게가 다른 것을 같은 카드로 줄줄이 / 한 단어만 색·굵게 / 점으로 이은 긴 한 줄 / 장식 번호(순서 없는 번호) / 제목 아래 되풀이 설명 / 한 화면에 강한 색 상자가 둘 이상) + 큰 글씨 확인 |
| 7절(관련 문서) | 이 문서 링크 |

기존 규칙(문구·상태·확인 방식·토큰)은 **하나도 지우거나 바꾸지 않았다.** 위는 모두 더한 것이다.

## 7. 확인 못 한 것

- 가이드의 다른 파일(`references/` 등)이 있는지는 보지 않았다(`frontend-design` 폴더에는 `SKILL.md`와 `LICENSE.txt`만 있었다).
- 큰 글씨(글자 150%) 점검은 시안 단계에서 한 번 해 보자는 제안이고, 실제 화면에서 깨지는 곳이 있는지는 아직 모른다.
