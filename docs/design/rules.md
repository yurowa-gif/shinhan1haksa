# 디자인 규칙 (D1)

> 소유: DESIGN 세션. 코딩 세션은 화면을 만들 때 이 문서와 `src/ui/Styles.html`만 따르면 된다.
> 바뀌는 것은 PR 설명의 "계약 변경"에 적는다. 이 문서에 백틱으로 적은 토큰(`--accent`)·클래스(`.pill.s-confirmed`)는
> `tests/design/styles.test.js`가 `Styles.html`에 실제로 있는지 검사한다.

대상은 휴대폰을 한 손으로 드는 고등학교 교사(저녁 자습 시간, 서서 걷는 중일 수 있음)와 학생·학부모다. 그래서 "작게 많이"보다 "크게 하나씩"을 따른다.

## 1. 기준

| 항목 | 규칙 | 이유 |
| --- | --- | --- |
| 화면 너비 | 360px(세로)에서 가로 스크롤이 없다. 고정 너비는 360px을 넘기지 않고, 긴 글은 줄바꿈한다 | 가장 작은 휴대폰 기준 |
| 누르는 칸 | 높이·너비 모두 48px 이상(`--tap`). 버튼·탭·목록 줄·칩 전부. 누르는 칸끼리 8px(`--gap-sm`) 이상 띄운다 | 한 손 엄지, 장갑·급한 손 |
| 기본 글자 | 18px(`html`에서 정하고, 나머지는 `rem`). 보조 글자는 `.muted`(0.9rem)까지만 작게. 0.8rem 아래로 내리지 않는다 | 큰 글씨 |
| 주 버튼 | 화면당 하나. 아래 고정 바(`.actionbar`)에 둔다. 보조 버튼은 `.btn.secondary`, 되돌릴 수 없는 동작은 `.btn.danger` | 엄지가 닿는 아래쪽 |
| 한 손 조작 | 위쪽 모서리까지 손을 뻗어야 하는 동작을 만들지 않는다. 뒤로 가기는 머리 왼쪽 `.back`, 저장·확정은 아래 바 | |
| 입력 | 글자 입력을 줄인다: 선택(칩·`segmented`)·검색 선택을 먼저, 직접 입력은 마지막 | 30초 입력(F1) |
| 색 | 색만으로 뜻을 전하지 않는다(4절). 글자 대비 4.5:1 이상(`tests/design/styles.test.js`가 검사) | 흑백 인쇄·색각 차이 |
| 효과 | 애니메이션·깜박임·무한 스크롤 없음. 화면은 새로고침·버튼으로 다시 불러온다 | 실시간 기능 없음 |
| 학생·학부모 화면 *(D13 제안)* | **처음 쓰는 사람 기준.** 학교 말(퇴실 대상·OUT·사전 특이사항)에는 뜻을 한 줄 붙인다. 점(·)으로 이은 긴 줄 대신 줄을 나눈다. 홈 맨 위는 "지금 해야 할 일" 한 칸(없으면 생략). 다른 사람의 이름·전화·상담 내용은 쓰지 않는다 | 가족·학생은 화면을 처음 본다 |

## 2. 화면 틀

위에서 아래로 세 덩어리다.

```
┌──────────────────────────┐
│ ← 처음으로   화면 제목    │  header.top (위에 붙음)   .back + h1
├──────────────────────────┤
│  본문: .card 들            │  main (휴대폰 한 줄, 840px~ 두 열 — 2-1절)
│  …                         │  하단 바가 있으면 main.has-actionbar
├──────────────────────────┤
│ [ 보조 ]   [ 주 버튼 ]     │  .actionbar (아래에 고정)
└──────────────────────────┘
```

- **머리:** `header.top` — 뒤로(`.back`, 높이 48px) + 제목(`h1`, 한 줄). 제목은 명사형이 아니라 하는 일("특이사항 입력")로 쓴다.
- **본문:** 내용은 `.card`로 묶는다. 한 카드에 제목(`h2`) 하나. 카드 사이 12px.
- **하단 작업 바:** 저장·확정·다음처럼 이 화면의 핵심 동작만 둔다. 버튼 1~2개(많아도 3개). 바가 있는 화면은 `<main class="has-actionbar">`로 해서 본문 끝이 가려지지 않게 한다. 바 안 `.btn`은 가로로 나눠 갖는다.
- **상태 줄:** 오류·안내는 본문 맨 위에 `.error`/`.notice`로 둔다. 서버를 부르는 중에는 버튼을 `disabled`로 바꿔 두 번 눌리지 않게 한다.
- **빈 화면:** "없습니다"만 쓰지 말고 다음에 할 일을 쓴다("아직 기간이 없습니다. 아래에서 첫 기간을 추가해 주세요.").
- **입력 한 칸:** `.field` — 라벨(위) → 입력 → 힌트(`.hint`) → 고칠 점(`.fix`). 오류가 있는 칸은 `.field.invalid`(테두리가 굵고 빨갛게)와 `.fix`의 글자를 함께 쓴다.

### 2-1. 반응형·마우스·키보드 *(D15 ②, 결정 85 보강 — 자세한 것은 `docs/design/refresh/responsive.md`)*

스타일은 **휴대폰 기준으로 쓰고, 넓어질 때만 더한다.** 중단점은 세 개다.

| 폭 | 이름 | 배치 |
| --- | --- | --- |
| ~599px | 휴대폰 | 한 줄. 홈은 맨 위 한 줄 → **해야 할 일** → 참고 순. 시트는 아래에서 올라오는 바텀 시트 |
| 600~839px | 태블릿·좁은 창 | 한 줄, `main` 최대 760px, 좌우 24px |
| 840px~ | 노트북 | 홈·넓은 화면(`main.home`·`main.wide`)은 **두 열**(왼쪽 해야 할 일 3 : 오른쪽 참고 2, 참고는 위에 붙음), 역할이 둘 이상이면 **왼쪽 역할 메뉴(레일)**, 폼 화면은 880px에서 멈춤. 시트는 **가운데 대화창**(560px), 아래 바는 내용 폭에 맞춰 오른쪽 끝 |

- **홈은 "오늘 할 일 목록"**: `UI.layoutHome`이 카드를 맨 위 한 줄(`.home-head`) / 해야 할 일(`.home-main` = `card todo`·`card key`) / 참고(`.home-side`)로 놓는다. 할 일이 없으면 "지금 처리할 일이 없습니다." 한 줄(카드를 지우지 않는다).
- **표·격자:** 상자(`.tablewrap`) 높이를 70dvh로 제한해 아래 가로 스크롤바가 늘 보이게 하고, **머리 행·이름 열은 고정**(불투명 바탕), 가로로 더 있으면 오른쪽 가장자리에 그림자 단서.
- **마우스·키보드:** `hover`는 색 변화만(정보를 hover에만 두지 않는다), 포커스 링은 모든 누르는 것·`iframe`에 보인다, Tab 순서는 화면 순서, **Enter = 주 버튼 누르기**(아래 한 줄)·Esc로 시트 닫기(닫으면 눌렀던 곳으로 초점이 돌아간다). 윈도우 크롬은 `scrollbar-gutter: stable`.
- **휴대폰:** 입력 글자 16px 이상(아이폰 확대 방지, 지금 18px), `100dvh`·`env(safe-area-inset-*)`, 시트 안 주 버튼은 시트 본문 흐름 맨 아래(아이폰 키보드에 고정 바가 가려지므로).
- **제안(미적용): 마우스에서 누르는 칸 40px 허용.** 근거: WCAG 2.2 대상 크기 최소 24px(2.5.8 AA)이고 48px은 터치 기준이다. 하지만 학교 노트북은 터치 화면일 수 있어 `pointer: fine`만으로 판정하기 어렵고, 기기 행렬 도구(`npm run devices`)와 `styles.test.js`가 48px로 검사한다. 줄 높이를 줄이고 싶으면 **누르는 칸 높이는 두고 줄 사이 여백만** 줄인다. 선생님 결정이 나면 `--tap`을 `@media (pointer: fine)`에서만 바꾼다.
- **Enter(총괄 결정, D15 ④):** 한 줄 입력칸에서 맨 Enter는 그 화면 **주 버튼을 누른 것**과 같다. 주 버튼이 확인 시트를 여는 화면(`UI.actionBar` 버튼 설명에 `enter: true`)은 시트가 뜨고, **확인 없이 바로 기록하는 화면에는 `enter`를 달지 않아** Enter가 아무 일도 안 한다. 여러 줄 칸(textarea)·선택 칸·버튼 위·Shift/Ctrl 조합·한글 입력 중(`isComposing`)·시트가 열려 있을 때는 동작하지 않는다(`UI.util.enterPressesPrimary`). 적용: 프로그램 저장, 명단 저장, 입퇴실 신청. 나머지 화면은 확인 시트가 생기면 `enter: true`를 단다.
- **글자 크기 이름 4개(총괄 결정, D15 ④):** 제목 `--font-xl`(1.5rem) · 소제목 `--font-lg`(1.1rem) · 본문 `--font-base`(18px) · 보조 `--font-sm`(.9rem ≈ 16px). **값은 줄이지 않는다**(입력 16px 이상, 본문 18px 유지 — 접근성 우선). `--font-xs`는 `--font-sm`의 옛 이름이라 같은 값이다(14px대 글자를 16px로 올림). 아직 남은 예외(화면 파일 안의 작은 글자: 달력 칸·결과 격자·시설 표 .72~.85rem)는 칸이 빽빽한 표라 화면별로 판단해 코딩 세션과 정한다.

## 3. 토큰

화면 파일은 새 색·크기를 직접 쓰지 않고 `var(--이름)`만 쓴다. 필요한 토큰이 없으면 만들지 말고 DESIGN에 요청한다(PR 댓글).

| 종류 | 토큰 | 쓰임 |
| --- | --- | --- |
| 바탕·글자 | `--bg` `--card` `--text` `--muted` `--line` `--field-line` | 화면 바탕(아주 옅은 푸른 회색), 흰 판, 본문, 보조 글자, 구분선, **입력칸·테두리 버튼의 테두리**(흰 바탕과 3:1 이상) |
| 주 색 | `--accent` `--accent-weak` `--accent-ink` `--on-accent` `--on-accent-muted` | 감색(결정 88). 머리줄·주 버튼·선택됨 / 연한 바탕 / 연한 바탕 위 글자 / **감색 면 위 글자** / 감색 면 위 보조 글자 |
| 강조 색 | `--signal` `--signal-ink` | 살구색(결정 88). **진짜 할 일**(마감·미처리 건수가 0보다 클 때)의 숫자·알약에만. 0건이면 쓰지 않는다 |
| 경고·오류 | `--warn` `--warn-weak` | 오류 글자·위험 버튼 / 오류 바탕 |
| 확정(초록) | `--ok` `--ok-ink` `--ok-weak` | 확정됨·안내(확인) |
| 요청·주의(노랑) | `--caution-ink` `--caution-weak` `--caution-line` | 요청 상태·안내(경고) |
| 취소·끝남(회색) | `--muted-ink` `--muted-weak` | 취소됨·비활성 |
| 코드 | `--code-hak-ink` `--code-hak-weak` / `--code-ga-ink` `--code-ga-weak` / `--code-byung-ink` `--code-byung-weak` | 학·가·병 |
| OUT | `--out1-ink` `--out1-weak` `--out1-line` / `--out2` `--out2-ink` | 1OUT / 퇴실 대상 |
| 크기 | `--tap`(48px) `--bar-h`(72px) `--font-base` `--font-sm` `--font-xs` `--font-lg` `--font-xl` | 누르는 칸, 하단 바, 글자 |
| 간격·모양 | `--gap-sm`(8) `--gap`(12) `--gap-lg`(16) `--radius`(12) `--radius-sm`(12) `--radius-pill` `--shadow` `--focus` | 번지는 그림자는 쓰지 않는다(`--shadow`는 아래 고정 바의 경계선) |
| 아이콘 | `--i-check` `--i-ellipsis` `--i-ban` `--i-triangle-alert` `--i-octagon-alert` `--i-circle-dot` `--i-info` `--i-refresh-cw` `--i-chevron-right` | Lucide 선 아이콘(ISC). 바깥 요청 없이 `Styles.html` 안에 들어 있다. 4절 |

글자색 이름이 `-ink`인 토큰은 같은 계열 `-weak` 바탕 위에서만 쓴다(대비를 맞춰 둔 짝이다).

**색을 정한 방법(결정 88, `docs/design/principles.md`):** 화면의 대부분은 회색 단계와 여백이다. 센 색은 감색(머리줄·주 버튼·선택됨)과 살구색(처리할 건수) 둘뿐이고, 상태 색(확정 초록·주의 호박·위험 빨강)은 옅은 바탕 + 진한 글자 한 가지 뼈대다. 화면 파일에 16진수 색을 직접 쓰지 않는다(`Styles.html`도 `:root` 밖에서는 토큰만 쓴다). 굵기는 400·700 두 단계, 본문 자간은 0이다.

**글꼴(결정 88):** `Styles.html`의 `font-family`는 `"Pretendard Variable", "Pretendard", "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` 순서다. **Pretendard를 웹폰트로 받는다**(SIL OFL 1.1, 눈누에서 웹 임베딩 사용 가능 확인 — `docs/design/concepts2/concepts2.md` 8절). `Styles.html` 맨 위의 `<link>` 한 줄이 jsDelivr에서 버전을 못 박은(v1.3.9) 조각 글꼴 CSS를 받고, 브라우저는 화면에 쓰인 글자가 든 조각만 내려받는다(시안 측정: 화면당 200~330KB, 그 뒤는 브라우저가 기억). **못 받으면(학교 망 차단·느림) 기기 기본 한글 글꼴로 그대로 보인다** — 글꼴이 늦게 오면 글자 모양만 바뀌고 화면은 멈추지 않는다(`font-display: swap`). 바깥에서 받는 것은 이 한 줄뿐이고(`tests/design/docs.test.js`가 검사), 다른 글꼴을 더하려면 (1) 라이선스(OFL 등)의 웹 임베딩 허용을 확인하고 (2) 학교 망에서 로딩 시간을 재어 총괄에게 보고한 뒤 결정한다. 실제 학교 망에서의 로딩 시간은 아직 재지 못했다(시험 배포에서 잰다).

## 4. 상태 표시

상태는 `.pill`(꼬리표) 하나로 보인다. **모양은 하나**(테두리 없는 꼬리표, 모서리 6px — 결정 85·88). 구분은 **앞 아이콘 + 낱말 + 색**이다. 아이콘은 Lucide 선 아이콘(결정 88: 예전의 글자 기호 ✓ … ⊘ ▲ ⛔ ● 를 바꿈)이고, 낱말(확정·요청…)은 반드시 글자로 쓴다(`tests/design/styles.test.js`가 앞 아이콘이 서로 다른지, 꼬리표에 테두리 모양이 다시 생기지 않는지 검사한다). 학·가·병은 글자 자체가 다르다. 긴 낱말은 알약 안에서 줄을 바꾼다(글자 150%에서 넘치지 않게).

| 뜻 | 클래스 | 보이는 모양 | 낱말 예 |
| --- | --- | --- | --- |
| 확정 | `.pill.s-confirmed` | 초록 · 체크 아이콘 | 확정 |
| 요청 | `.pill.s-requested` | 호박 · 점 셋 아이콘 | 요청 |
| 취소 | `.pill.s-canceled` | 회색 · 금지 아이콘 · 취소선 | 취소 |
| 학(학원) | `.pill.c-hak` | 파랑 | 학 |
| 가(가정) | `.pill.c-ga` | 보라 | 가 |
| 병(병결 계열) | `.pill.c-byung` | 청록 | 병결·병지·병조 |
| 1OUT | `.pill.out-1` | 호박 · 세모 경고 아이콘 | 1OUT |
| 퇴실 대상 | `.pill.out-2` | 빨강 바탕 흰 글자 · 팔각 경고 아이콘 | 퇴실 대상 |
| 처리할 일 | `.pill.todo` | 살구색 · 점 아이콘 | 확인 필요 |
| 보조 | `.pill.mute` | 회색 | 현재 |

- **카드는 세 가지뿐이다(결정 85 구조, 결정 88 모양):** 참고 정보 = 상자 없음(줄로만 나눔) / 진짜 할 일 = `card todo`(흰 판 + 가는 테두리, **마감·미처리 건수가 0보다 클 때만**, 0건이면 상자 없이 줄) / 중요한 숫자·상태 = `card key`(같은 흰 판, OUT처럼 늘 보여야 하는 것). 색 띠·번지는 그림자는 쓰지 않는다. `UI.cardClass(kind)`로 붙인다.
- **다른 화면으로 가는 링크는 `UI.rowLink`(한 줄, 48px — 글자는 본문색, 끝에 화살표 아이콘)**, 일을 하는 버튼(저장·확정)만 `.btn`이다. 할 일 카드의 첫 줄 링크만 폭 가득 주 버튼 모양이 된다.
- 학생·학부모 화면은 `body.tone-soft`. **교사 화면과 같은 안이다(결정 88)** — 달라지는 것은 본문 폭(720px)·판 사이 여백·내 OUT 꼬리표 크기뿐이다.
- 알림 개수는 `.count`(감색 바탕 밝은 숫자)에 "3"처럼 숫자를 넣는다. 아이콘 단독 배지는 쓰지 않는다.
- 안내 줄도 앞 아이콘이 있다: `.error`·`.notice.warn`(세모 경고), `.notice.ok`(체크), `.notice.info`(정보).
- 아이콘 출처: Lucide Icons(ISC). `Styles.html` 머리 주석에 출처를 적고, 라이선스 전문은 `design/preview/concepts2/icons/LICENSE`에 둔다.
- 출석부 인쇄물(흑백)은 이 색을 쓰지 않는다. 인쇄 규칙은 `docs/design/print-sheet-spec.md`(D4 이후).

## 5. 문구

화면에 보이는 모든 글(버튼·카드 설명·안내·오류·빈 상태·확인 시트·알림)의 기준은 **[`docs/design/writing.md`](writing.md)** 하나다(자료조사 세션 W1 제안을 받아들여 옮김, 결정 85). 고칠 문구 목록은 [`writing-audit.md`](writing-audit.md). 이 문서에는 모양 규칙만 남긴다. 다만 **개인 정보** 규칙은 글쓰기 규칙이 아니라 보안 규칙이라 여기에 둔다: 건강 정보(사유 메모)를 목록·출석부·알림에 길게 쓰지 않고 유형 약어까지만 쓴다(예: "병결"). 빈 상태는 한 줄 사실 + 있으면 다음 행동(`UI.emptyState`).

## 6. 확인·사유 입력이 필요한 동작

실수로 누르면 되돌리기 어렵거나 다른 사람 기록에 영향을 주는 동작은 한 번 더 묻는다. 묻는 방식은 두 가지다.

- **확인**: `UI.confirmSheet`(D3). 아래에서 올라오는 시트에 "무엇이 바뀌는지" 한 줄 + [취소]·[동작 이름] 버튼. 기본 포커스는 취소 쪽.
- **사유 입력**: `UI.confirmWithReason`(D3). 위와 같고 사유 입력칸(필수)이 있다. 사유는 `audit_log`에 남는다.

| 동작 | 방식 | 이유 |
| --- | --- | --- |
| 특이사항 취소(F1) | 사유 입력 | 기록은 지우지 않고 status를 '취소'로 바꾼다. 왜 취소했는지 남긴다 |
| 특이사항 요청을 취소(출결 담당) | 사유 입력 | 요청한 교사에게 알려야 한다 |
| OUT 취소(F4) | 사유 입력 | 학생 불이익에 직접 연결 |
| 퇴실 확정(F4·F6) | 확인 + 학부모 면담 기록 확인 | 유예 없음. 되돌리려면 재입실 기록이 필요 |
| 학사·기숙사 입퇴실 변경(F6) | 확인(적용일을 크게 보여 줌) | 출석부·급식에 바로 반영 |
| 급식 변경(F7) | 확인(적용일과 이유 한 줄: "11:30 이후 신청이라 3월 4일부터") | 적용일 계산이 규칙이라 예상과 다를 수 있다 |
| 근무 교대(F3) | 확인(상대 교사에게 알림이 간다는 문구 포함) | 알림이 나간다 |
| 좌석 맞바꾸기(F5) | 확인(두 학생 이름과 자리) | 두 기록을 한 번에 고친다 |
| 좌석 배치를 다시 만들기(F5 자동 초안) | 확인 | 수동 수정을 덮어쓴다 |
| 운영 안 함으로 바꾸기(F13·C4) | 확인(그날 출석부가 사라진다는 문구) | 출석부·특이사항에 영향 |
| 명단 업로드 저장(C3) | 확인(신규·변경·퇴실 후보 개수) | 한 번에 여러 탭에 쓴다 |
| 계정·역할 변경 | 확인 | 권한이 바뀐다 |
| 진로·탐구 기록 학부모 공개(F15·F16) | 확인(누구에게 보이는지) | 학생 개인정보 공개 |

묻지 않는 동작: 저장(되돌릴 수 있는 일반 입력), 조회, 필터, 화면 이동. 취소는 "지우기"가 아니라 "취소 처리"라고 부른다(기록은 남는다).

## 8. 화면을 그리기 전 한 줄 계획과 점검 *(D13 제안, `docs/design/frontend-design-review.md` 6절)*

새 화면·큰 변경은 시안(또는 코드)을 시작하기 전에 **계획 3줄**을 적고, 끝나고 **점검 6줄**을 본다. 시안 설명 문서·PR 설명에 한 번씩 적는다.

**계획(누가 · 일 · 눈에 띌 것)**

1. 누가 쓰나(역할, 처음 쓰는 사람인가)
2. 이 화면의 일 한 가지(제목이 하는 일이다)
3. 가장 눈에 띄어야 할 것 **하나**(지금 해야 할 일·경고·주 버튼)

**점검(걸리면 고친다)**

| 점검 | 어떻게 고치나 |
| --- | --- |
| 무게가 다른 정보를 같은 카드로 줄줄이 나열했나 | 중요한 한 가지를 맨 위로, 나머지는 조용히(같은 `.card`라도 순서·`.muted`로 무게를 나눈다) |
| 제목이나 문장에서 **한 단어만** 색·굵게 했나 | 상태 알약·경고 상자처럼 뜻이 있는 곳에만 강조한다 |
| 점(·)으로 이은 긴 한 줄이 있나 | 줄을 나누거나 낱말 하나로 줄인다(교사용 훑어보기 목록은 예외) |
| 순서가 없는데 번호를 붙였나 | 번호는 순서가 있는 내용(단계)에만 쓴다 |
| 카드 제목 바로 아래에 같은 말을 되풀이하는 설명이 있나 | 뜻을 더하지 않으면 지운다 |
| 한 화면에 강한 색 상자(`.notice.warn`·`.pill.out-2`·`.btn.danger`)가 둘 이상인가 | 하나만 남기고 나머지는 보통 `.notice.info`·`.pill.mute`로 낮춘다 |

학생·학부모 화면은 한 가지를 더 본다: **기기 글자 크기를 키운 모양**(예: 150%)에서도 한 줄이 잘리거나 버튼이 겹치지 않는지.
