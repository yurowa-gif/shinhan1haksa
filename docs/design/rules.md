# 디자인 규칙 (D1)

> 소유: DESIGN 세션. 코딩 세션은 화면을 만들 때 이 문서와 `src/ui/Styles.html`만 따르면 된다.
> 바뀌는 것은 PR 설명의 "계약 변경"에 적는다. 이 문서에 백틱으로 적은 토큰(`--accent`)·클래스(`.pill.s-confirmed`)는
> `tests/design/styles.test.js`가 `Styles.html`에 실제로 있는지 검사한다.

대상은 휴대폰을 한 손으로 드는 고등학교 교사(저녁 자습 시간, 서서 걷는 중일 수 있음)와 학생·학부모다. 그래서 "작게 많이"보다 "크게 하나씩"을 따른다.

## 1. 기준

| 항목 | 규칙 | 이유 |
| --- | --- | --- |
| 화면 너비 | 360px(세로)에서 가로 스크롤이 없다. 고정 너비는 360px을 넘기지 않고, 긴 글은 줄바꿈한다 | 가장 작은 휴대폰 기준 |
| 누르는 칸 | 높이·너비 모두 48px 이상(`--tap`). 버튼·탭·목록 줄·칩 전부. 누르는 칸끼리 8px(`--gap-sm`) 이상 띄운다 | 한 손 엄지, 장갑·급한 손 |
| 기본 글자 | 18px(`html`에서 정하고, 나머지는 `rem`). 보조 글자는 `.muted`(0.9rem)까지만 작게. 0.8rem 아래로 내리지 않는다 | 큰 글씨 |
| 주 버튼 | 화면당 하나. 아래 고정 바(`.actionbar`)에 둔다. 보조 버튼은 `.btn.secondary`, 되돌릴 수 없는 동작은 `.btn.danger` | 엄지가 닿는 아래쪽 |

| 입력 | 글자 입력을 줄인다: 선택(칩·`segmented`)·검색 선택을 먼저, 직접 입력은 마지막 | 30초 입력(F1) |
| 색 | 색만으로 뜻을 전하지 않는다(4절). 글자 대비 4.5:1 이상(`tests/design/styles.test.js`가 검사) | 흑백 인쇄·색각 차이 |
| 효과 | 애니메이션·깜박임·무한 스크롤 없음. 화면은 새로고침·버튼으로 다시 불러온다 | 실시간 기능 없음 |

## 2. 화면 틀

위에서 아래로 세 덩어리다.

```
┌──────────────────────────┐
│ ← 처음으로   화면 제목    │  header.top (위에 붙음)   .back + h1
├──────────────────────────┤
│  본문: .card 들            │  main (최대 720px, 좌우 16px)
│  …                         │  하단 바가 있으면 main.has-actionbar
├──────────────────────────┤
│ [ 보조 ]   [ 주 버튼 ]     │  .actionbar (아래에 고정)
└──────────────────────────┘
```

- **머리:** `header.top` — 뒤로(`.back`, 높이 48px) + 제목(`h1`, 한 줄). 제목은 명사형이 아니라 하는 일("특이사항 입력")로 쓴다.
- **본문:** 내용은 `.card`로 묶는다. 한 카드에 제목(`h2`) 하나. 카드 사이 12px.
- **하단 작업 바:** 저장·확정·다음처럼 이 화면의 핵심 동작만 둔다. 버튼 1~2개(많아도 3개). 바가 있는 화면은 `<main class="has-actionbar">`로 해서 본문 끝이 가려지지 않게 한다. 바 안 `.btn`은 가로로 나눠 갖는다.
- **상태 줄:** 오류·안내는 본문 맨 위에 `.error`/`.notice`로 둔다. 서버를 부르는 중에는 버튼을 `disabled`로 바꿔 두 번 눌리지 않게 한다.
- **빈 화면:** "없습니다"만 쓰지 말고 다음에 할 일을 쓴다("아직 기간이 없습니다. 아래에서 첫 기간을 추가해 주세요.").
- **입력 한 칸:** `.field` — 라벨(위) → 입력 → 힌트(`.hint`) → 고칠 점(`.fix`). 오류가 있는 칸은 `.field.invalid`(테두리가 굵고 빨갛게)와 `.fix`의 글자를 함께 쓴다.

## 3. 토큰

화면 파일은 새 색·크기를 직접 쓰지 않고 `var(--이름)`만 쓴다. 필요한 토큰이 없으면 만들지 말고 DESIGN에 요청한다(PR 댓글).

| 종류 | 토큰 | 쓰임 |
| --- | --- | --- |
| 바탕·글자 | `--bg` `--card` `--text` `--muted` `--line` | 화면 바탕, 카드, 본문, 보조 글자, 구분선 |
| 주 색 | `--accent` `--accent-weak` `--accent-ink` | 링크·주 버튼·선택됨 / 연한 바탕 / 연한 바탕 위 글자 |
| 경고·오류 | `--warn` `--warn-weak` | 오류 글자·위험 버튼 / 오류 바탕 |
| 확정(초록) | `--ok` `--ok-ink` `--ok-weak` | 확정됨·안내(확인) |
| 요청·주의(노랑) | `--caution-ink` `--caution-weak` `--caution-line` | 요청 상태·안내(경고) |
| 취소·끝남(회색) | `--muted-ink` `--muted-weak` | 취소됨·비활성 |
| 코드 | `--code-hak-ink` `--code-hak-weak` / `--code-ga-ink` `--code-ga-weak` / `--code-byung-ink` `--code-byung-weak` | 학·가·병 |
| OUT | `--out1-ink` `--out1-weak` `--out1-line` / `--out2` `--out2-ink` | 1OUT / 퇴실 대상 |
| 크기 | `--tap`(48px) `--bar-h`(72px) `--font-base` `--font-sm` `--font-xs` `--font-lg` `--font-xl` | 누르는 칸, 하단 바, 글자 |
| 간격·모양 | `--gap-sm`(8) `--gap`(12) `--gap-lg`(16) `--radius`(12) `--radius-sm`(10) `--radius-pill` `--shadow` `--focus` | |

글자색 이름이 `-ink`인 토큰은 같은 계열 `-weak` 바탕 위에서만 쓴다(대비를 맞춰 둔 짝이다).

**글꼴:** `Styles.html`의 `font-family`는 `"Pretendard", "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` 순서다. **글꼴 파일을 내려받지 않는다**(`@font-face`·`<link>` 없음, 결정: 총괄 권장 채택). 그래서 Pretendard가 깔린 기기에서만 그 글꼴이 쓰이고, 나머지는 기기 기본 한글 글꼴(안드로이드 Noto Sans, 아이폰 Apple SD 고딕, 윈도우 맑은 고딕)로 나온다. 이유: 학교 망에서 글꼴 내려받기 지연, 외부 요청 없음(개인정보·차단 걱정 없음), 모양이 기기마다 조금 달라도 업무 화면 읽기에 지장이 없다. 글꼴을 불러오려면 먼저 (1) 그 글꼴의 라이선스(OFL 등)가 웹 임베딩을 허용하는지 확인하고 (2) `HtmlService`에서 로딩 시간을 학교 망에서 재어 총괄에게 보고한 뒤 결정한다(그 전에는 코드에 넣지 않는다).

## 4. 상태 표시

상태는 `.pill`(둥근 표) 하나로 보인다. **색 + 앞 글자(모양) + 테두리 + 낱말**을 모두 쓰므로 흑백 인쇄·색각 차이에서도 구분된다. 낱말(확정·요청…)은 반드시 글자로 함께 쓴다.

| 뜻 | 클래스 | 보이는 모양 | 낱말 예 |
| --- | --- | --- | --- |
| 확정 | `.pill.s-confirmed` | 초록 · ✓ · 실선 | ✓ 확정 |
| 요청 | `.pill.s-requested` | 노랑 · … · 점선 테두리 | … 요청 |
| 취소 | `.pill.s-canceled` | 회색 · ⊘ · 점선 · 취소선 | ⊘ 취소 |
| 학(학원) | `.pill.c-hak` | 파랑 · 실선 | 학 |
| 가(가정) | `.pill.c-ga` | 보라 · 이중선 테두리 | 가 |
| 병(병결 계열) | `.pill.c-byung` | 청록 · 파선 테두리 | 병결·병지·병조 |
| 1OUT | `.pill.out-1` | 주황 · ▲ | ▲ 1OUT |
| 퇴실 대상 | `.pill.out-2` | 빨강 바탕 흰 글자 · ⛔ | ⛔ 퇴실 대상 |
| 처리할 일 | `.pill.todo` | 파랑 · ● | ● 확인 필요 |
| 보조 | `.pill.mute` | 회색 | 현재 |

- 알림 개수는 `.count`(빨강 바탕 흰 숫자)에 "3"처럼 숫자를 넣는다. 아이콘 단독 배지는 쓰지 않는다.
- 안내 줄도 앞 글자가 있다: `.error`(⚠), `.notice.warn`(⚠), `.notice.ok`(✓), `.notice.info`(ⓘ).
- 출석부 인쇄물(흑백)은 이 색을 쓰지 않는다. 인쇄 규칙은 `docs/design/print-sheet-spec.md`(D4 이후).

## 5. 문구

| 항목 | 규칙 | 예 |
| --- | --- | --- |
| 버튼 | 하는 일을 동사로. "확인"·"OK"만 쓰지 않는다 | "저장", "취소 처리", "출석부 열기", "맞바꾸기" |
| 날짜 | "3월 3일(수)". 해가 다르면 "2027년 3월 3일(수)". 숫자 날짜(2027-03-03)는 입력칸에서만 | 3월 3일(수) |
| 시각 | 24시간제 "18:30". 오전·오후를 쓰지 않는다. 24시는 "24:00" | 18:30–20:00 |
| 기간 | "3월 3일(수)–3월 5일(금)", 시각 범위는 "18:00–20:00" | |
| 이름 | 학생은 "1. 김가온"(학년. 이름). 학번·이메일을 화면에 길게 쓰지 않는다 | 1. 김가온 |
| 존댓말 | 해요체가 아니라 합니다·해 주세요체로 짧게 | "저장했습니다." |
| 오류 | 무엇이 문제인지 + 무엇을 하면 되는지. 시스템 말("오류 500")은 쓰지 않는다 | "시작일이 종료일보다 늦습니다. 시작일을 앞날로 고쳐 주세요." |
| 권한 없음 | 이유와 가야 할 곳을 쓴다 | "권한이 없습니다. 출결 담당 선생님께 요청해 주세요." |
| 저장 성공 | 한 줄 확인 + 결과. 화면을 가리는 알림창을 쓰지 않는다 | "저장했습니다." |
| 빈 상태 | 다음 할 일을 쓴다 | "오늘 특이사항이 없습니다." |
| 상태 낱말 | `docs/contracts/vocabulary.md`의 값 그대로(확정·요청·취소, 입실·퇴실…) | |
| 개인 정보 | 건강 정보(사유 메모)를 목록·출석부·알림에 길게 쓰지 않는다. 유형 약어까지만 | "병결" |

## 6. 확인·사유 입력이 필요한 동작

실수로 누르면 되돌리기 어렵거나 다른 사람 기록에 영향을 주는 동작은 한 번 더 묻는다. 묻는 방식은 두 가지다.

- **확인**: `UI.confirmSheet`(D3). 아래에서 올라오는 시트에 "무엇이 바뀌는지" 한 줄 + [취소]·[동작 이름] 버튼. 기본 포커스는 취소 쪽.
- **사유 입력**: `UI.confirmWithReason`(D3). 위와 같고 사유 입력칸(필수)이 있다. 사유는 `audit_log`에 남는다.

| 동작 | 방식 | 이유 |
| --- | --- | --- |
| 특이사항 취소(F1) | 사유 입력 | 기록은 지우지 않고 status를 '취소'로 바꾼다. 왜 취소했는지 남긴다 |
| 특이사항 요청을 취소(출결 담당) | 사유 입력 | 요청한 교사에게 알려야 한다 |
| OUT 취소(F4) | 사유 입력 | 학생 불이익에 직접 연결 |
| 퇴실 확정(F4·F6) | 확인 + 학부모 면담 기록 확인 | 유예 없음. 되돌리려면 재입실 기록이 필요 |
| 학사·기숙사 입퇴실 변경(F6) | 확인(적용일을 크게 보여 줌) | 출석부·급식에 바로 반영 |
| 급식 변경(F7) | 확인(적용일과 이유 한 줄: "11:30 이후 신청이라 3월 4일부터") | 적용일 계산이 규칙이라 예상과 다를 수 있다 |
| 근무 교대(F3) | 확인(상대 교사에게 알림이 간다는 문구 포함) | 알림이 나간다 |
| 좌석 맞바꾸기(F5) | 확인(두 학생 이름과 자리) | 두 기록을 한 번에 고친다 |
| 좌석 배치를 다시 만들기(F5 자동 초안) | 확인 | 수동 수정을 덮어쓴다 |
| 운영 안 함으로 바꾸기(F13·C4) | 확인(그날 출석부가 사라진다는 문구) | 출석부·특이사항에 영향 |
| 명단 업로드 저장(C3) | 확인(신규·변경·퇴실 후보 개수) | 한 번에 여러 탭에 쓴다 |
| 계정·역할 변경 | 확인 | 권한이 바뀐다 |
| 진로·탐구 기록 학부모 공개(F15·F16) | 확인(누구에게 보이는지) | 학생 개인정보 공개 |

묻지 않는 동작: 저장(되돌릴 수 있는 일반 입력), 조회, 필터, 화면 이동. 취소는 "지우기"가 아니라 "취소 처리"라고 부른다(기록은 남는다).
