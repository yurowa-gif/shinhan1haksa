# 후속 목록 (검토에서 남긴 것)

총괄 검토 마지막 라운드에서 막히는 문제가 없으면 병합하고, 남은 것은 여기에 적는다.
그 기능을 만들거나 연결할 때 먼저 읽고, 끝나면 `[x]`와 PR 번호를 적는다.

## R5 OutRules — #30 (2단계 F4에서 연결할 때)
- [ ] 테스트 추가: 앞선 자동 OUT이 다른 이유(유형 변경·중복)로 취소된 묶음에서도 유지 행을 고를 때 `since`가 적용된다(변이 O43이 지금 살아남음).
- [ ] `autoTypeSince`는 설정 행의 `updated_at`이 아니라 **유형별로 마지막으로 넓힌 시각**(audit_log)에서 읽는다. 다른 칸을 고쳐도 `updated_at`이 바뀌기 때문이다. F4에 연결하기 전에 `rules-api.md` 상세 절도 같이 고친다.
- [ ] 알려진 지름길(계약에 적혀 있음): 유형을 좁혔다가 다시 넓힌 뒤, 확정 시각이 섞인 묶음에서 `since` 뒤 행을 취소하면 OUT이 첫 넓힘 전 행을 대표로 남는다. OUT이 더 남을 뿐 잘못 취소되지는 않는다. 설정에 넓힘 이력을 두면 고칠 수 있다.
- [ ] 학생을 정정한 뒤 `per`를 group→row로 바꾸면 moved 표시가 대표 행 단위에만 남는다(드문 관리자 경로).

## R6 MealRules — #31 (2단계 F6·F7에서 연결할 때)
- [ ] **재입실(퇴실 되돌림)** 때 퇴실 정리 F6 급식 행(조식 `미실시`@퇴실일, 석식 `미실시`@중단일)과 퇴실로 취소된 신청 행을 되돌리는 규칙이 없다. 재현: 3/8 퇴실(3/10) → 3/11 재입실 → 석식은 3/15부터, 조식은 3/10부터 계속 미실시. F6 재입실 계약에서 정한다.
- [ ] 테스트 추가: 퇴실 → 재입실 → 두 번째 퇴실을 늦게 입력한 경우, 퇴실 중인 날은 가장 늦은 퇴실 행으로 막힘·중단일을 정한다(변이 M45가 지금 살아남음).
- [ ] 퇴실 행의 `requested_at`은 **날짜+시각 전체**가 있어야 한다. 비었거나 날짜뿐이면 지름길(이 신청 일시)이 쓰여 입력 순서에 다시 의존한다. F6 저장 때 검사한다.
