# 권장 이수 과목 자료조사 범위·방법 (RS1)

> 2026-11-06 자료조사 세션 작성. F15(6단계)에서 "희망 학과의 권장 이수 과목"을 보여 줄 자료의 범위와 수집 규칙.
> **대상 대학 목록은 선생님 확인 전 후보안이다.** 확인 후 이 문서의 2절을 고친다.

## 1. 무엇을 모으나

- 대학이 **공식으로 발표한** 모집단위(학과·계열)별 고교 권장 이수 과목.
- 결과 파일: `data/course_recommendations/course_recommendations.csv`
  - 열: `base_year,university,unit,core_courses,recommended_courses,source_url,source_title`
  - 과목은 `;`로 구분하고, 과목명은 2022 개정 교육과정 고시 과목명(`standard_courses_2022.csv`)으로 맞춘다. 원문 표기가 다르면 `course_name_map.csv`에 대응을 남긴다.
- 앱에서는 **참고 정보**로만 보여 준다(판정하지 않음, PRD F15). 화면에 출처·기준 연도를 늘 함께 표시한다.

## 2. 대상 대학 후보안 (선생님 확인 필요)

조사 방법: 웹 검색으로 **대학·대교협 공식 도메인에 문서가 실제로 게시되어 있는지**만 확인했다. 언론·학원·블로그 요약은 존재 근거로만 보고, 과목 내용은 쓰지 않는다.

**주의: 지금 세션 네트워크에서는 대학·대교협 사이트를 열 수 없어서(8절) 아래 문서들의 본문은 아직 읽지 못했다.** "공식 문서 확인"은 공식 주소에 그 제목의 문서가 게시된 것을 검색 결과로 확인했다는 뜻이다.

## 3. 기준 연도(`base_year`) 정의 — 제안

- **`base_year` = 그 자료가 적용되는 대입 학년도**(문서 제목의 "2028학년도"). 발표 연도가 아니다.
- 우리 학교 학생과의 대응(모두 2022 개정 교육과정):

| 입학 연도 | 대입 학년도 | 비고 |
| --- | --- | --- |
| 2025 | 2028 | 지금 2학년 |
| 2026 | 2029 | 지금 1학년 |
| 2027 | 2030 | 2027년 3월 입학 |

- 가정: 학생의 대입 학년도 자료가 아직 없으면(예: 2029·2030) **가장 가까운 이전 base_year 자료를 보여 주고 "○○학년도 기준 자료"라고 표시**한다. 앱 쪽 표시 규칙은 F15 구현 때 총괄이 확정한다.

## 4. 핵심·권장 구분이 없는 대학

대학마다 표현이 다르다(핵심/권장, 권장만, "권장하는 과목", "미제시").

| 원문 | CSV 처리 |
| --- | --- |
| 핵심과 권장을 나눔 | `core_courses`, `recommended_courses`에 나눠 넣는다 |
| 구분 없이 "권장"만 | 모두 `recommended_courses`, `core_courses`는 비운다(핵심으로 올리지 않는다) |
| 모집단위가 "미제시"(진로에 따라 자유 선택) | 행을 넣고 두 과목 칸을 모두 비운다. 앱은 "대학이 과목을 제시하지 않음"으로 보여 준다 |
| 과목이 아닌 조건(예: "과학 진로선택 3과목 이상", "제2외국어 또는 한문 1과목 이상") | **열린 질문(7절 1번).** 정해지기 전에는 조건 문장을 과목 칸에 넣지 않고 `docs/research/conditions-pending.md`에 모아 둔다 |
| 계열 단위로만 발표(예: "자연계열 전체") | `unit`에 원문 계열명을 그대로 쓴다(예: `자연계열 전체`) |

## 6. 수집 규칙

1. 공식 문서만 쓴다. 2차 자료뿐이면 `docs/research/needs-check.md`("확인 필요" 목록)에 둔다. 추측으로 채우지 않는다.
2. 내려받은 PDF는 커밋하지 않는다(저작권·용량). `sources.csv`에 문서명·발행 기관·URL·발행일·열람일·쪽만 남긴다.
3. 원문의 과목 표기(띄어쓰기, Ⅰ/I 등)가 표준 과목명과 다르면 `course_name_map.csv`에 원문 → 표준을 남긴다. 2015 개정 과목명(예: 물리학Ⅱ)처럼 하나로 대응되지 않는 것은 대응하지 않고 확인 필요로 둔다.
4. 개인정보는 다루지 않는다(대학 문서에도 없지만, 테스트가 이메일·전화번호 패턴을 검사한다).
5. 대학 묶음마다 PR 하나.

## 7. 열린 질문 (총괄·선생님)

1. **조건형 권장(과목 목록이 아닌 것)을 어떻게 담을까?** 예: 연세대 "과학 진로선택 3과목 이상", 서울대 "제2외국어/한문 1과목 이상". 지금 열(7개)로는 담을 곳이 없다. 기본안: `note` 열 하나를 추가(설정 시트 `course_recommendations` 탭도 6단계에 같은 열). 결정 전에는 4절대로 따로 모은다.
2. 대상 대학 목록(2절) 확정. 수도권 다른 대학을 넣을지.
3. `base_year` 정의(3절)와 "가까운 이전 자료로 대신 보여 주기" 가정.
